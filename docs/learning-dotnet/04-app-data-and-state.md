## index.ts: باب الواجهة

يستورد `registerRootComponent` من Expo و`App` من الملف المحلي ثم ينفذ `registerRootComponent(App)`. هذا يعرّف المكوّن الجذري لبيئة React Native ويهيئ تسجيله. التعليقات تشرح التسجيل، ولا تنفذ تعليمات. تسجيل الجذر لا يعني أن كل مكتبات حاتم تعمل داخل كل إصدار Expo Go؛ المرجع العملي لهذه النسخة هو البناء الأصلي عبر Xcode/Expo.

## App.tsx: كل الأسطر

الأسطر ١–١٢ تجمع مكونات React Native، شريط الحالة، المناطق الآمنة، تحميل الخط، أربعة أوزان عربية، الشاشتين الرئيسيتين، الألوان، وتخصيص مستند الويب.

`App()` مكوّن React. `useFonts` في الأسطر ١٥–٢٠ يحمل أوزان IBM Plex Sans Arabic ويعيد `loaded` و`fontError`. إن كان التحميل مستمرًا بلا خطأ، نعرض spinner. عند النجاح أو وجود خطأ خط، نكمل الشاشة حتى لا يصبح فشل الخط شاشة انتظار أبدية.

الأسطر ٢١–٢٨ تختار الرحلة:

```tsx
const web = Platform.OS === "web";
const organizerPreview =
  web &&
  new URLSearchParams(window.location.search).get("preview") === "organizer";
```

`window` خاص بالمتصفح. `&&` يمنع الوصول إليه عند التشغيل الأصلي. Query مثل `?preview=organizer` يسمح بمعاينة المنظّم في المتصفح للتطوير؛ لا يعطي مفتاح أي مجموعة موجودة. بعدها regular expression يأخذ رمزًا من `/join/<code>` مكوّنًا من حروف وأرقام و`_` و`-` مع سماح بشرطة مائلة أخيرة. `?.[1]` يقرأ أول مجموعة التقاط إذا حصلت المطابقة، و`?? null` يجعل الغياب صريحًا.

الأسطر ٢٩–٤٤ تعيد شجرة الشاشة: `SafeAreaProvider` يوفّر قياسات المساحة الآمنة، View يملأ الشاشة بخلفية موحدة، WebDocument يضبط المتصفح فقط، StatusBar يختار نصًا داكنًا. الفرع الأول انتظار الخط؛ الثاني ويب بدون معاينة فيعرض InviteScreen حتى لو code=null؛ الأخير يعرض Organizer على الهاتف أو في المعاينة.

لا يوجد router عام هنا. المنظّم يبدل أربعة تبويبات بحالة محلية، والويب له مدخل دعوة بسيط. هذا اختيار حجم، لا قاعدة عامة أن كل تطبيق يجب أن يستغني عن navigation library.

## client.ts: الاتفاق مع الخادم، الأسطر ١–١٢

`components` قادمة من ملف الأنواع المولّد. مثلًا:

```tsx
export type Preferences = components["schemas"]["Preferences"];
```

هذا يعيد استعمال وصف Preferences الذي وُلد من OpenAPI. ليس استدعاء شبكة، ولا نسخة من كائن Preferences وقت التشغيل. aliases الأخرى: Experience وGroupView باسم Group وSettings وMember وDecision وInviteView باسم Invite. `Session` شكل محلي `{groupId, token}` لحفظ وصول المنظّم؛ ليس نموذج حساب جلسة على الخادم.

## الأسطر ١٤–٢٦: ثلاث بيئات وثلاثة معاني للعنوان

| أين يعمل العميل؟ | API_ORIGIN | PUBLIC_ORIGIN |
|---|---|---|
| المتصفح | نص فارغ؛ الطلب إلى نفس الموقع | `window.location.origin` |
| محاكي iOS | `http://localhost:8000` على الماك | العنوان العام من EXPO_PUBLIC_API_URL |
| iPhone فعلي | العنوان المضبوط في EXPO_PUBLIC_API_URL | نفس العنوان المضبوط |

`isDevice` يميز الجهاز الفعلي من المحاكي. الأصل المضبوط له افتراضي localhost، لكنه ليس إعدادًا صحيحًا للوصول من هاتف فعلي إلى الماك: localhost على الهاتف يعني الهاتف نفسه. شغلي النفق أولًا ثم ابنِي التطبيق بعنوانه عند اختبار جهاز فعلي.

فصل PUBLIC_ORIGIN ضروري: المحاكي قد يتصل محليًا، لكن الرابط الذي يرسله إلى الأعضاء يجب أن يكون عامًا. متغيرات `EXPO_PUBLIC_` تدخل حزمة العميل؛ لا تضعي فيها سرًا. العنوان ليس مفتاح صلاحية. تغيير `.env.local` لا يغيّر تلقائيًا حزمة Release المثبتة؛ تحتاج إعادة بناء.

## الأسطر ٢٨–٨٧: request<T> خطوة خطوة

`ApiError` يمدد Error ليحمل status. `super(message)` يهيئ رسالة الخطأ في النوع الأب. الدالة request تستقبل مسارًا وخيارات اختيارية: method، token، body، signal، وتعيد Promise للنوع T.

1. الأسطر ٤٦–٤٩ تنشئ AbortController ومؤقتًا ١٢ ثانية، وتربط signal خارجيًا إن أُرسل. الـwrapper يدعم ذلك؛ نداءات api الحالية لا تمرر signal من الشاشات.
2. الأسطر ٥١–٦٠ تبني URL من الأصل و`/api` والمسار. الافتراضي GET، وContent-Type هو JSON، وAuthorization يضاف فقط عند وجود token. `JSON.stringify` يحول body إلى نص؛ لا يرسل body إن كان undefined. `signal` يتيح إلغاء fetch.
3. `response.ok` يعني HTTP ناجحة. استجابة HTTP 404 لا تجعل fetch يرمي تلقائيًا؛ نحن نفحصها.
4. 5xx تتحول لرسالة عربية عامة دون محاولة عرض HTML أو تفاصيل داخلية.
5. في أخطاء العميل يحاول قراءة JSON. `.catch(() => ({}))` تعطي كائنًا فارغًا إن لم يكن صالحًا. يستخدم `detail` إذا كان نصًا، وإلا رسالة عامة.
6. عند النجاح يقرأ JSON ويفترض `as T`. هذا لا يعمل runtime validation؛ العقد المولّد يساعد وقت كتابة الكود فقط.
7. catch يعيد ApiError المعروف كما هو. أخطاء الشبكة/الإلغاء تتحول إلى ApiError برقم 0، وهو ترميز محلي وليس HTTP status صادرًا من الخادم.
8. finally يمسح المؤقت والمستمع كي لا تبقى موارد مرتبطة بطلب انتهى.

## الأسطر ٨٩–١٢٥: واجهة api الصغيرة

هذا كائن يجمع دوال استخدام request. أسماء الدوال توضح مقصد الشاشة:

| الدالة | ما تضيفه للطلب؟ |
|---|---|
| `catalog` | GET experiences، النتيجة Experience[] |
| `create` | POST groups وبداخله `{preferences}`، النتيجة GroupCreated |
| `group` | معرف المجموعة ومفتاح المنظّم |
| `settings` | PUT إعدادات كاملة مع مفتاح المنظّم |
| `profile` | PUT تفضيلات المنظّم |
| `remove` | DELETE معرف عضو داخل المجموعة |
| `invite` | GET عرض مشترك برمز الدعوة |
| `join` | POST تفضيلات عضو جديد إلى الدعوة |
| `me` | GET ملف العضو بمفتاحه |
| `updateMe` | PUT تعديل ملف العضو بمفتاحه |

الدوال arrow مثل `(s: Session) => request(...)` مجرد اختصار لدالة تستقبل s وترجع Promise. ليست آلية سحرية لـAPI. لا نكرر ضبط headers ورسائل الأخطاء في كل شاشة.

`emptyPreferences` في الأسطر ١٢٧–١٣٥ قيم بدء النموذج: اسم فارغ، مقيم، قوائم فارغة، false للنباتي والحار، و٢٠٠ للميزانية. الاسم الفارغ مناسب **للنموذج قبل الحفظ**، وليس طلبًا صالحًا لإنشاء مجموعة.

## schema.d.ts: ملف مولّد، لا خادم مولّد

`.d.ts` يصف أنواعًا فقط. `paths` يربط المسارات بطرق HTTP والمدخلات والردود. `components.schemas` يصف الأنواع المشتركة. `?` تعني حقلًا اختياريًا في الوصف، و`never` يعني أن ذلك الموضع لا يملك قيمة مسموحة في النوع، و`unknown` يعني أن التوثيق لم يحدد شكلًا أدق. أقواس الأسماء المتداخلة هي indexed access types وليست استعلام قاعدة بيانات.

مصدر الحقيقة Models/controllers → OpenAPI → هذه الأنواع. `npm run types:api` يعيد التوليد. لا تعدّلي schema.d.ts لإصلاح backend؛ سيختفي تعديلك في التوليد التالي. هذه الأداة توثّق endpoints التي كتبناها، ولا تنشئ منطق CRUD جاهزًا بدل كتابة الخادم.

## storage.ts: الأسطر ١–٣٩

الأسطر ١–١٩ تستورد AsyncStorage للويب وSecureStore للمنصة الأصلية وتضع واجهة مشتركة `get/set/remove`. كل دالة تختار التنفيذ عبر `Platform.OS`. تحفظ نصًا بمفتاح، لا Group كاملة؛ البيانات الدائمة الأساسية في DB وراء API.

الأسطر ٢١–٣٩ `readSession` تقرأ `hatim.organizer.v1`. إذا لم توجد قيمة ترجع null. إذا وجدت، `JSON.parse` إلى unknown ثم فحص أنها object غير null وبها `groupId` و`token` من نوع string. عند فساد JSON أو الشكل ترجع null بدل انهيار التطبيق. هذا فحص شكل محلي؛ صلاحية المفتاح لا تُعرف إلا من الخادم.

SecureStore يستعمل تخزين المنصة المخصص للمعلومات الحساسة. AsyncStorage في المتصفح ليس له نفس حماية keychain. ومسح بيانات المتصفح يفقد مفتاح العضو المحلي؛ لا توجد استعادة حساب هنا. هذه نتيجة تصميم الوصول البسيط، لا عطل في الخوارزمية.

## useOrganizer.ts: لماذا custom hook؟

`Organizer.tsx` يحتاج بيانات المجموعة وأفعال الحفظ. بدل خلط كل منطق الشبكة في JSX، تجمعه `useOrganizer()` وتعيد واجهة صغيرة للشاشة.

### الأسطر ١٣–٤٢: الذاكرة والاستعادة

| الاسم | نوعه ودوره |
|---|---|
| `session` | مفتاح المجموعة المحفوظ أو null |
| `group` | آخر Group جاءت من الخادم أو null |
| `loading` | استعادة البدء قيد العمل |
| `busy` | عملية حفظ قيد العمل؛ يؤثر في الأزرار |
| `error` | نص فشل لعرضه أو null |
| `writing` | ref لقفل فوري يمنع حفظين متزامنين |
| `epoch` | ref لرقم يتغير عند بدء تعديل لمنع رد قراءة قديم من استبدال نتيجة أحدث |

`restore` تمسح الخطأ وتبدأ loading، وتقرأ session. إن وجدت تطلب المجموعة. إذا رجع 404 تحذف المفتاح المحلي وتفرغ الحالة؛ الخادم لا يتعرف على هذا الوصول. أخطاء الاتصال الأخرى تُعرض ولا تحذف مفتاحًا صالحًا لمجرد انقطاع الشبكة. finally تنهي loading. effect يستدعي restore عند تركيب المكوّن. `useCallback([], ...)` هنا يثبت مرجع restore لأنها لا تحتاج قيمة متغيرة من الرسم.

### الأسطر ٤٣–٧٤: التحديث كل ست ثوانٍ

إذا لا session لا يبدأ polling. `alive` يمنع كتابة state بعد تنظيف effect، و`fetching` يمنع تداخل طلبين من نفس دورة التحديث. refresh تتخطى الحفظ الجاري والطلب الجاري ووجود التطبيق في الخلفية. تلتقط رقم epoch، تطلب المجموعة، ثم تقبل الرد فقط إن ظل effect حيًا ولا توجد كتابة ولم يتغير الرقم.

مثال المشكلة التي يمنعها epoch: بدأ GET للخطة ذات ٩ خانات، ثم حفظتِ خانة واحدة، ثم وصل GET القديم متأخرًا. بلا فحص الإصدار سيعيد الشاشة إلى ٩ رغم نجاح الحفظ. مع الرقم يُهمل الرد القديم. هذا ضبط محلي لواجهة واحدة؛ ليس نظام حل تعارضات لكل الأجهزة على الخادم.

`setInterval(refresh, 6000)` تحديث دوري، وAppState listener يحدّث عند العودة للنشاط. cleanup يغيّر alive ويمسح المؤقت ويفصل listener. ليست WebSockets أو تحديثًا لحظيًا مضمونًا؛ عادة يظهر تغيير العضو في دورة تالية مع زمن الشبكة.

### الأسطر ٧٥–٩٠: run

`run` تستقبل دالة async. إن كانت كتابة قائمة تعود فورًا، وإلا ترفع القفل ورقم epoch وbusy وتمسح الخطأ. تنتظر العمل. عند الفشل تحفظ الرسالة **ثم تعيد رمي الخطأ** حتى يعرف النموذج أنه لم يحفظ، فلا يغلق نفسه كنجاح. finally تزيل القفل وbusy مهما كانت النتيجة. ref يلزم لأن state update لا يبدّل قيمة busy فورًا في نفس لحظة النقرة.

### الأسطر ٩١–١٢١: ما يرجع للشاشة؟

يرجع group/loading/busy/error/restore وأربعة أفعال. `create` ينشئ المجموعة، يأخذ id وorganizer_token، يحفظهما محليًا، ثم يضع session وgroup. `settings` و`profile` و`remove` تنفّذ API بالمفتاح ثم تستبدل Group بنتيجة الخادم. كل الأفعال داخل run. `if (session)` تحميها من العمل دون جلسة محلية.

هذه ليست optimistic updates: لا نعتمد خطة متوقعة على الواجهة قبل رد الخادم. نعتمد النتيجة التي أعادها الخادم، بما فيها أسباب المنع والتعديلات. النموذج قد يحتفظ بمسودة، لكن المجموعة الرسمية تأتي من API.

## تمرين فهم

تخيلي أنك أغلقتِ التطبيق: أي بيانات تضيع من useState؟ وأي مفتاح يبقى في storage؟ وأين تبقى أسماء الأعضاء؟ الإجابة: حالة الشاشة محلية مؤقتة، المفتاح في تخزين الجهاز، وأعضاء المجموعة في SQLite. عند الفتح تعيد restore ربطها. إذا كانت الخدمة مطفأة فلن تكفي صورة التطبيق المثبتة وحدها لإعادة بناء الخطة.
