# ٥ — المكونات والتصميم وLiquid Glass

[الفهرس](README.md) · [التالي: الشاشات](06-screens.md)

هذه الملفات تعرض بيانات وتستقبل أفعالًا من الأب. لا تستعلم مباشرة من DB، ولا تقرر وحدها ما إذا كانت تجربة مناسبة للمجموعة.

## theme.ts: قاموس الشكل

[الملف](../../src/theme.ts) يحتوي ثلاثة أجزاء: `colors` أسماء دلالية لألوان مثل الخلفية والحبر والأخضر والخط الفاصل والتحذير؛ `fonts` أسماء أوزان IBM Plex التي حمّلناها في App؛ و`ar(n)` تنسيق عدد بـ`toLocaleString("ar-SA")`. تغيير اللون في القاموس يغير كل المواضع التي تستخدم هذا المفتاح. بعض التفاصيل لها ألوان خاصة داخل StyleSheet أيضًا؛ ليست كل قيمة بصرية مركزية حاليًا.

`photos: Record<string, number>` يربط تسعة مفاتيح `fire/sushi/levant/pasta/breakfast/bao/pizza/coffee/dessert` بملفات الصور. في React Native قيمة `require(image)` معرف مورد للحزمة وليست نص URL. الاستيرادات ثابتة حتى يعرف bundler أي ملفات يضمّنها. يجب أن يطابق `Image` في Experience مفتاحًا موجودًا هنا.

## معجم كل خصائص التنسيق المتكررة

`StyleSheet.create({...})` يجمع أنماطًا مسماة. `style={[s.base, condition && s.extra, style]}` يركب الأنماط بالترتيب، واللاحق يغلب السابق عند تعارض الخاصية. الأرقام في React Native عادة وحدات منطقية مرتبطة بالعرض، وليست دائمًا بكسلات الصورة الفيزيائية.

| الخاصية | ما تغيره؟ |
|---|---|
| `flex: 1` | يأخذ الحيز المرن المتاح داخل تخطيط الأب |
| `flexDirection: "row-reverse"` | ترتيب صف من الطرف المعاكس لدعم التخطيط العربي |
| `flexWrap: "wrap"` | إن لم تتسع العناصر، ينتقل بعضها إلى سطر آخر |
| `justifyContent` | توزيع على المحور الرئيسي؛ center أو space-between أو space-around |
| `alignItems` / `alignSelf` | محاذاة الأبناء / هذا العنصر على المحور الآخر |
| `gap` | فراغ بين الأبناء، دون زيادة حول أطراف الحاوية |
| `padding` | مسافة داخل الحدود؛ Horizontal أفقي وVertical رأسي |
| `margin` | مسافة خارج العنصر؛ قد تكون سالبة لتداخل صور الأشخاص |
| `width`, `height` | الأبعاد؛ النسبة المئوية تُحسب نسبة للحاوية |
| `minWidth`, `minHeight` | أقل حجم؛ مهم لمساحة لمس الأزرار |
| `maxWidth`, `maxHeight` | حد يمنع تمدد النص أو النافذة أكثر من اللازم |
| `backgroundColor`, `color` | لون الحاوية / لون النص |
| `#RRGGBB` / `rgba(...)` | لون سداسي / لون مع درجة شفافية |
| `borderWidth`, `borderColor` | سماكة ولون الحد |
| `borderRadius` | تدوير الزوايا؛ توجد خصائص لكل زاوية أيضًا |
| `overflow: "hidden"` | قص الصورة أو الزجاج عند حدود الحاوية |
| `position: "absolute"` مع top/right/bottom/left | وضع عنصر فوق آخر نسبة لحاويته، مثل شارة على صورة |
| `StyleSheet.absoluteFill` | اختصار يملأ مساحة الحاوية بتموضع مطلق |
| `zIndex` | ترتيب التراكب بين عناصر متداخلة |
| `opacity` | شفافية، تُستعمل لاستجابة الضغط والتعطيل |
| `transform: [{scale: ...}]` | تكبير/تصغير بصري صغير عند الضغط |
| `boxShadow` | ظل حول العنصر؛ لا ينفذ قاعدة عمل |
| `fontSize`, `fontFamily`, `lineHeight` | حجم وخط وارتفاع سطر النص |
| `textAlign`, `writingDirection` | محاذاة النص واتجاه كتابته؛ الرابط يحتاج ltr |
| `letterSpacing` | تقارب الحروف في عناوين محددة |

كل StyleSheet في الشاشات يعيد تركيب هذه الخصائص لأجزاء مختلفة. العدد ٢٤ مثلًا ليس قاعدة سرية؛ اختيار مسافة/حجم في التصميم. تغيير خط قد يحتاج تعديل lineHeight كي لا يُقص النص العربي.

## ui.tsx: عناصر مشتركة بدل تكرارها

[الملف](../../src/components/ui.tsx)، ٣٥٥ سطرًا. الاستيرادات ١–١٩ تجلب primitives ومكتبات الزجاج والتمويه والأيقونات والمساحة الآمنة والألوان. `colors as c` اسم مختصر محلي، و`type ReactNode` يصف ما يمكن وضعه كأبناء React.

### T، الأسطر ٢١–٢٩

يغلف Text. يستخرج style وweight الافتراضي regular، ويمرر باقي props إلى Text بـ`...props`. نوعه تقاطع `TextProps & {weight?...}`، أي كل خصائص Text مع وزن خط خاص بنا. `keyof typeof fonts` يسمح بأسماء أوزان القاموس فقط. يطبق اتجاه النص ولونه الأساسي والخط المختار ثم style المرسل من الأب. لهذا يمكنك كتابة `<T weight="semibold">حاتم</T>` في كل مكان دون إعادة اسم الخط الطويل.

### Row، الأسطر ٣٠–٣٢

يغلف View بـ`s.row`: صف معكوس الاتجاه، محاذاة وسطية، وفراغ بين العناصر. يقبل ViewProps كي تضيفي أسلوبًا أو أبناء. لا ينفذ loop؛ اسمه فقط يصف التخطيط.

### Glass، الأسطر ٣٣–٥٦

يفحص المنصة ثم `isLiquidGlassAvailable()`. إن كان iOS والميزة متاحة يستخدم GlassView بالأسلوب regular ولون scheme فاتح وtint شفاف. وإلا يستخدم BlurView بشدة ٤٥ وخلفية بيضاء شبه شفافة. كلاهما يعرض children داخل شكل `s.glass` نفسه.

هذه ميزة نظام فعلية عندما تتوفر، وتختلف عن مجرد تخفيض opacity. لا نفترض أن المتصفح يرسم نفس تأثير iOS. [توثيق Expo GlassEffect للإصدار ٥٧](https://docs.expo.dev/versions/v57.0.0/sdk/glass-effect/).

### Button، الأسطر ٥٧–١٠٤

props: النص، دالة الضغط، هل هو ثانوي، نوع أيقونة، busy، disabled، small. `icon: Icon = ArrowLeft` يستقبل خاصية اسمها icon ويعيد تسميتها إلى Icon لأن عناصر JSX المخصصة تبدأ بحرف كبير.

Pressable يصف زرًا لقارئ الشاشة، يعطل التفاعل عند disabled أو busy، ويختار نمط الضغط. الثانوي خلفيته sage، والصغير أقل padding مع حد لمس ٤٤. النص يغير لونه وحجمه بحسب النمط. إن busy يعرض spinner مكان الأيقونة؛ وإلا يعرض Icon. لا يحفظ شيئًا بنفسه، بل ينادي onPress المرسل.

### IconButton، الأسطر ١٠٥–١٣٨

زر أيقونة بمربع لمس ٤٤. `label` وصف وصول لأن الأيقونة وحدها لا تكفي للقارئ. light يعطي خلفية شفافة فاتحة فوق الصور، active يغير الخلفية ويملأ الأيقونة، pressed يغير الشفافية. الفعل الحقيقي يظل onPress من الأب.

### Chip، الأسطر ١٣٩–١٨٨

يبني محتوى مشتركًا من نص وأيقونة اختيارية. إذا وُجد onPress يرسم Pressable مع accessibilityState.selected ولون الاختيار. إذا لم يوجد يرسم View صغيرة كتسمية معلومات فقط. لذلك Chip قد تكون فلترًا قابلًا للضغط أو شارة غير تفاعلية؛ غياب الفعل ليس خطأ.

### Sheet، الأسطر ١٨٩–٢٣٤

Modal شفافة تظهر من الأسفل مع animation slide. `visible` يحدد الظهور و`onRequestClose` يعالج طلب النظام للإغلاق. KeyboardAvoidingView تضيف إزاحة مناسبة على iOS كي لا تغطي لوحة المفاتيح الحقول. خلفية Pressable تملأ المساحة وتغلق عند الضغط خارج الورقة. SafeAreaView تحمي الأسفل، مع مؤشر سحب مرسوم كخط وعنوان وزر إغلاق. الخط تجميلي؛ لا يوجد هنا gesture مخصص للسحب.

داخلها ScrollView بـ`keyboardShouldPersistTaps="handled"` كي تتمكن الأزرار من التعامل مع الضغط عند ظهور لوحة المفاتيح. children تُعرض بفراغ منتظم. الورقة بعرض لا يتجاوز ٦٢٠ وارتفاع أقصى ٩٣٪. هذا مكوّن عام تستخدمه تفاصيل التجربة والتفضيلات والدعوة والحذف.

### Notice، الأسطر ٢٣٥–٢٥٨

نص داخل بطاقة ملاحظة. warning يغير الخلفية واللون ويصفها `alert` لقارئ الشاشة. هذا مجرد عرض للرسالة التي وصلت، لا يحوّل رسالة إلى استثناء أو يعالجها.

### Empty، الأسطر ٢٥٩–٢٨١

أيقونة وعنوان وشرح عندما لا توجد بيانات/نتائج. يضعها في الوسط. empty state جزء من المنتج: فشل البحث أو اكتمال الوجبات لا يجب أن يكون مساحة بيضاء بلا تفسير.

### StyleSheet، الأسطر ٢٨٣–٣٥٥

`text` و`row` أساس العربية. `glass` قص وحد شفاف وزوايا. `button/secondary/iconButton/chip` أشكال التفاعل التي سبقت. `backdrop/sheet/handle/sheetHeader` تنظيم الورقة من الخلفية إلى عنوانها. `notice` padding ولون الملاحظة. كل خصائص هذه الكتل مُعرّفة في معجم أول الفصل.

## Toggle.tsx: زر تبديل واحد قابل للوصول

[الملف](../../src/components/Toggle.tsx)، ٤٢ سطرًا. يستورد Pressable وView وHost وSwitch من Expo UI والألوان. props أربعة: value boolean، دالة onValueChange، label، testID للاختبار.

الغلاف Pressable هو هدف اللمس الوحيد، بدور switch وحالة checked. عند الضغط يرسل `!value`. داخل الغلاف View بـ`pointerEvents="none"` وإخفاء وصول الأبناء، حتى لا يصبح لدينا هدفا لمس أو إعلانان لقارئ الشاشة لنفس التحكم. Host يحدد اللون والحجم ويحتوي Switch ليعطي الشكل الأصلي. تغيير value يعود من الأب؛ الزر لا يملك نسخة ثانية مستقلة من التفضيل.

هذه النسخة تستخدم مكونات Expo UI العامة من `@expo/ui`، والتي توفر دعم المنصات؛ لم نكتب فرع switch HTML يدويًا هنا. [Expo UI](https://docs.expo.dev/versions/v57.0.0/sdk/ui/).

## MealControl.tsx: الوقت مسودة ثم حفظ

[الملف](../../src/components/MealControl.tsx)، ١٠٨ أسطر. يستقبل slots وconsumed وonChange تعيد Promise وbusy. `draft` تبدأ من slots. effect يعيد مزامنتها إذا تغيرت قيمة الخادم القادمة في props؛ تحريك slider يعدل draft فقط حتى الضغط على زر الحفظ.

الشاشة تعرض العنوان والعدد، ثم `.map` لثلاث اختصارات: ٩ خانات، ٥، ١. إذا كان consumed أكبر من الاختصار، لا نمرر onPress، فتظهر كتسمية دون فعل. slider يظهر ما دام المستهلك أقل من ٩. الحد الأدنى `Math.max(1, consumed)`، والأقصى ٩ والخطوة ١؛ `Math.round` يحول نتيجة التحكم إلى عدد صحيح. busy يعطله.

السطر التوضيحي يعرض المستهلك و`draft - consumed`. الزر يظهر فقط عند `draft !== slots`؛ ينادي `onChange(draft)`. الأب سيرسل الإعدادات إلى الخادم، والخادم يتحقق مرة أخرى. `card/icon/number` في StyleSheet تتحكم بشكل البطاقة وأيقونة الوقت والعدد الكبير.

## PreferencesForm.tsx: نموذج التفضيلات كاملًا

[الملف](../../src/components/PreferencesForm.tsx)، ٢٢٠ سطرًا. الأسطر ١–٢٨ تستورد الأدوات وتعرّف قائمة المطابخ والحساسيات. الأنواع `NonNullable<Preferences["cuisines"]>` وallergies تضمن توافق القيم المسموح اختيارها مع العقد المولّد.

الأسطر ٣٠–٥٥ تستقبل initial وonSave ونص زر افتراضي وbusy. `value` مسودة تبدأ من initial، وerror محلي. `patch(p)` يدمج الجزء المرسل في نسخة جديدة من المسودة:

```tsx
const patch = (p: Partial<Preferences>) => setValue((v) => ({ ...v, ...p }));
```

`v` آخر قيمة، والخصائص في p تأتي بعد النسخ فتستبدل نظيرتها. لا يغير هذا الخادم، ولا يغير props الأصلية. `save` ترفض الاسم الفارغ بعد trim، وتمسح الخطأ، ثم تنتظر onSave باسم مقلم. إذا فشل الوعد تحفظ رسالة الخطأ داخل النموذج حتى يعرف المستخدم أن العمل لم يُحفظ.

| كتلة JSX | وظيفتها وفعلها |
|---|---|
| الاسم | TextInput مرتبط بـvalue.name، وكل كتابة تنادي patch، وطول أقصى ٣٠، وتلميح إكمال الاسم |
| مقيم/زائر | زران يغيران role ويتبادلان حالة selected |
| المطابخ | map إلى Chips؛ الضغط يزيل المطبخ بـfilter إن كان موجودًا، أو يضيفه إلى نسخة المصفوفة إن لم يوجد |
| النباتي | Toggle يغير vegetarian، والنص يشرح أنه قيد |
| غير الحار | Toggle يغير mild، وهو تفضيل مرن في المخطّط |
| الحساسية | نفس إضافة/إزالة المطابخ، مع قائمة مختلفة وتحذير عند وجود عنصر واحد على الأقل |
| الميزانية | عرض الرقم وSlider بين ٣٠ و٥٠٠ بخطوة ١٠، مع التقريب قبل patch |
| نهاية النموذج | Notice عند الخطأ، Button ينادي save ويعرض busy، ثم شرح أن المنظّم يرى القيود |

`value.cuisines?.includes(...)` يتعامل مع حقل قد يكون اختياريًا حسب الأنواع المولّدة، و`?? []` يجعل الإضافة تعمل إن غاب. `!!value.allergies?.length` يحوّل عدد العناصر إلى boolean كي لا يرسم React الرقم صفر بدل إخفاء التحذير.

`initial` قيمة بدء عند تركيب النموذج، وليست effect ينسخ تغييرات props باستمرار. هذا مفيد حتى لا يمحو polling ما تكتبه المستخدمة في مسودتها، لكن لا تفترضي أن تغير initial من الأب يعيد ضبط قيمة النموذج تلقائيًا دون دورة حياة مناسبة.

`input/heading/caption/wrap/controlCard/line` في النهاية: الحقل بإطار واتجاه عربي، العنوان، الوصف الصغير، لف Chips، بطاقات التحكم، والخط الفاصل. معجم التنسيق يفسر كل خاصية فيها.

## ExperienceCard.tsx: بطاقة تجربة

[الملف](../../src/components/ExperienceCard.tsx)، ١٢٦ سطرًا. props: experience تُسمّى e للاختصار، onOpen، onSave اختيارية، saved، priority، compact. الصورة من photos[e.image]، والضغط عليها يفتح التفاصيل. compact يقلل ارتفاعها. شارة category أعلى الصورة، وزر Bookmark يظهر فقط عند وجود onSave ويتغير وصفه وactive بحسب saved.

جزء النص قابل للضغط أيضًا. يعرض الحي، والرتبة إن وجدت وإلا المطبخ، وعنوانًا بسطر واحد عبر numberOfLines، والمكان والمطبخ، ثم السعر للشخص والدقائق وأيقونة اتجاه. `ar` ينسق الأرقام. لا يحسب priority أو saved؛ الأب يمررهما.

الأنماط: `card` إطار وقص بزوايا؛ `image` صورة بعرض كامل؛ `category/bookmark` تراكب أعلى الصورة؛ `body` مسافات النص؛ `title/meta/subtitle` مستويات خط؛ `divider` فاصل. ظهور البطاقة في «اكتشف» لا يثبت أهلية التجربة؛ شاشة الاكتشاف تعرض الكتالوج، بينما الخطة تعتمد التقييم.

## WebDocument.tsx وWebDocument.web.tsx

النسخة العامة ثلاث أسطر تعيد null. Metro يختار ملف `.web.tsx` للويب تلقائيًا من نفس import. نسخة الويب تنفذ effect لتضع عنوان التبويب و`lang=ar`، وتضيف meta theme-color وstyle للخلفية وbox-sizing ولون التحديد وحد focus-visible. التنظيف يحذف العناصر التي أضافها effect. لا تعيد تعيين عنوان المستند/لغته في cleanup، ولا تضبط `dir=rtl` عالميًا؛ اتجاه النص والتخطيط مضبوط بالمكونات.

لا نحاول استعمال document في iOS. فصل الملفات حسب المنصة يمنع ذلك ويحافظ على استيراد بسيط في App.

## جرّبي بنفسك

ابني بطاقة باسم وسعر فقط، ثم اجعلي onOpen تطبع المعرف في الطرفية. أضيفي زر حفظ يغيّر حالة محلية قبل ربطه بالخادم. اختبري بلوحة المفاتيح وقارئ الشاشة: هل للزر اسم؟ هل يتضح اختياره؟ بعد فهم ذلك أضيفي الألوان ثم الزجاج. وظيفة المكوّن أولًا، ثم مظهره.
