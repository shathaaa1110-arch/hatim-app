## ماذا يعني برنامج؟

البرنامج تعليمات تتعامل مع بيانات. في حاتم البيانات مثل اسم الشخص وميزانيته. التعليمات مثل «إذا كان سعر التجربة أكبر من ميزانية أحد الأعضاء، سجّلي سبب منعها». الشاشة وسيلة إدخال وعرض؛ القرار نفسه يمكن اختباره بلا شاشة.

ملف الكود نص. المجلد يجمع ملفات مرتبطة. المحرّر مثل VS Code يساعدك على الكتابة. Terminal ينفّذ أوامر، مثل تشغيل الخادم. المتصفح يرسل طلبات إلى الخادم. Git يسجل نسخًا من ملفاتك؛ GitHub يستضيف مستودع Git. رفع الكود إلى GitHub لا يشغّل API تلقائيًا.

| دالة Function | تعليمات لها مدخلات ونتيجة | `Evaluate(experience, members)` |

| كائن Object | عدة خصائص تحت اسم | تفضيلات الشخص |
| قائمة Array | عناصر مرتبة | قائمة الحساسية أو التجارب |
| `null` | لا توجد قيمة هنا | لا توجد ركيزة مختارة |
| استثناء Exception | انتقال لمسار فشل | دعوة غير موجودة |
| مكتبة | كود جاهز يؤدي وظيفة محددة | رسم أيقونة أو قراءة SQLite |

## C# و.NET وASP.NET Core ليست أسماء لشيء واحد

تكتبين ملفًا امتداده `.cs` بلغة C#. أمر `dotnet build` يترجم مشروع C# ويتحقق من صحته. بيئة .NET تشغّل الناتج. ASP.NET Core يوفّر HTTP والتوجيه وقراءة JSON وحقن الخدمات. في حاتم مشروع الخادم داخل `backend/Hatim.Api`.

مثال تعليمي صغير، وليس دالة أخرى مخفية في التطبيق:

```csharp
int slots = 5;
int consumed = 2;
int remaining = slots - consumed;
Console.WriteLine(remaining);
```

`int` نوع عدد صحيح. `slots` اسم اخترناه. `=` إسناد قيمة وليس مقارنة. `;` تنهي التعليمة. السطر الثالث يطرح ٢ من ٥، والسطر الرابع يطبع ٣. `Console.WriteLine` دالة جاهزة للكتابة في الطرفية.

```csharp
bool FitsBudget(int price, int budget)
{
    return price <= budget;
}
```

`bool` يعني النتيجة true أو false. ما بين `()` مدخلان، وكل منهما عدد صحيح. `{}` تحتوي جسم الدالة. `return` تعيد النتيجة وتخرج. `FitsBudget(80, 100)` تعطي true. هذه تجربة لتعلّم الشرط، وليست كامل سياسة المخطّط.

| `null!` / `value!` | إسكات تحذير المترجم عن null؛ لا يصلح القيمة ولا يمنع null وقت التشغيل |
| `[Range(1, 9)]` | سمة metadata يستعملها نظام validation لفحص الحدود |
| `=>` | جسم تعبير مختصر، أو دالة صغيرة lambda بحسب الموقع |
| `x => x.Id` | خذي عنصرًا سمّيناه x وأعيدي معرفه |
| `$"هلا {name}"` | نص تُدخل فيه قيمة المتغير |
| `a ?? b` | استعملي b عندما تكون a تساوي null |
| `x?.Trim()` | نفذي Trim إن كانت x موجودة |
| `!x` / `a && b` / `a || b` | نفي / الشرطان معًا / واحد منهما يكفي |

| `condition ? a : b` | نتيجة a إذا تحقق الشرط، وإلا b |
| `List<T>` / `T[]` | قائمة قابلة للإضافة / مصفوفة من نوع T |

| `Func<Database, T>` | دالة تستقبل Database وتعيد قيمة من النوع T |

## JavaScript وTypeScript وTSX

واجهة التطبيق مكتوبة بـTypeScript: JavaScript مع وصف للأنواع يفحصه المترجم قبل التشغيل. ملف `.tsx` يسمح أيضًا بـJSX، أي وصف عناصر الشاشة داخل الدوال. ملف `.ts` للكود الذي لا يحتاج JSX. الأنواع لا تصبح حارسًا تلقائيًا للبيانات القادمة من الإنترنت.

```tsx
const [slots, setSlots] = useState(9);
```

هذا سطر من نفس أسلوب التطبيق: `const` يثبت ربط الاسم داخل هذه القراءة من المكوّن، و`useState` يعيد القيمة الحالية ودالة تغييرها. `setSlots(1)` يطلب من React رسم المكوّن بالقيمة الجديدة. لا تكتبي `slots = 1` متوقعة أن تعيد الشاشة رسم نفسها.

```tsx
<Button label="عشاء واحد" onPress={() => setSlots(1)} />
```

اسم العنصر `Button`. `label` و`onPress` خصائص props. النص ثابت، أما ما بين `{}` فهو تعبير برمجي. `() => ...` دالة مؤجلة حتى الضغط. لو كتبتِ `onPress={setSlots(1)}` فأنت تستدعينها أثناء الرسم بدل تمرير فعل للضغط.

| تركيب TS/JSX | المعنى |
|---|---|
| `import` / `export` | استخدام تعريف من ملف / إتاحته لملفات أخرى |
| `import type` | استيراد وصف نوع فقط؛ لا يحتاج كود تشغيل |
| `type Session = {...}` | اسم مختصر لشكل البيانات |
| `Promise<T>` | نتيجة T ستصل لاحقًا أو تفشل |
| `unknown` | لا نعرف النوع، افحصيه قبل الاستخدام |
| `as T` | إخبار TypeScript باعتقادنا عن النوع؛ لا يفحص JSON وقت التشغيل |
| `Partial<Preferences>` | جزء من خصائص التفضيلات |
| `NonNullable<T>` | إزالة null وundefined من وصف النوع |
| `keyof typeof fonts` | أسماء مفاتيح كائن الخطوط فقط |
| `{ ...old, slots: 1 }` | كائن جديد ينسخ الخصائص ثم يستبدل slots |
| `[...items, id]` | مصفوفة جديدة بها العناصر القديمة ومعرف جديد |
| `items.map(...)` | تحويل كل عنصر إلى نتيجة؛ مثل تحويل التجارب إلى بطاقات |
| `filter(...)` / `find(...)` | كل المطابقات / أول مطابقة أو undefined |
| `includes(x)` / `Set.has(x)` | هل العنصر موجود؟ |
| `?.` / `??` | قراءة آمنة لقيمة اختيارية / قيمة افتراضية عند الغياب |
| `!!value` | تحويل القيمة إلى boolean |
| `a === b` | مقارنة دون تحويل نوع ضمني |
| `key={id}` | هوية عنصر القائمة التي يستخدمها React عند إعادة الرسم |
| `<>...</>` | Fragment يجمع عناصر دون حاوية مرئية جديدة |
| `condition && <T>...</T>` | ارسم العنصر عند تحقق الشرط |
| `void load()` | تجاهل قيمة Promise في هذا الموضع؛ لا يعالج الفشل وحده |

الرمز `!` في نهاية قيمة TypeScript مثل `item!` تأكيد للمترجم أيضًا، وليس تحققًا وقت التشغيل. والرمز `%` في `index % 3` باقي القسمة، استُخدم لتكرار ثلاثة ألوان.

## React: props وstate وeffects

المكوّن دالة ترجع وصفًا للشاشة. `props` بيانات وأفعال يمررها الأب إلى الابن. `state` ذاكرة المكوّن التي تؤثر في رسمه. `useEffect` يربط وجود المكوّن بعمل خارجي، مثل التحميل أو مؤقّت. دالة التنظيف التي يعيدها effect توقف المؤقت عند زواله أو تغير اعتماداته.

`useRef` يحتفظ بقيمة بين مرات الرسم دون أن يؤدي تغييرها إلى رسم جديد. لذلك استعملناه لقفل الحفظ ولمرجع ScrollView. `useCallback` يحافظ على مرجع الدالة ما دامت اعتماداته لم تتغير. هذه أدوات لضبط دورة حياة البيانات؛ ليست بديلًا عن فهم من يملك كل قيمة. [مقدمة React الرسمية](https://react.dev/learn).

## HTTP وJSON: كيف تتكلم الواجهة والخادم؟

طلب HTTP يتكون من method ومسار وheaders وأحيانًا body. الخادم يعيد status وheaders وbody. JSON نص لنقل كائنات ومصفوفات؛ ليس قاعدة بيانات ولا لغة تعليمات.

```http
PUT /api/groups/example/settings
Authorization: Bearer <organizer-token>
Content-Type: application/json

{"slots":1,"anchor_id":"fire","pocket_ids":[],"completed_ids":[]}
```

`example` و`<organizer-token>` أماكن لقيم حقيقية، وليسا بيانات دخول تعمل. هذا الطلب يقول: حدّث إعدادات المجموعة. الـheader يثبت امتلاك مفتاحها. JSON يصف الإعدادات. الفراغ في `Bearer ` جزء من صيغة الـheader.

GET يقرأ، POST ينشئ هنا، PUT يستبدل بيانات المورد المعني، DELETE يحذف. النجاح المعتاد 200، والإنشاء 201. المشروع يستعمل 404 للمعرف/المفتاح غير الصحيح، 409 لاكتمال العدد، 413 لحجم الطلب، 422 لمدخلات غير صالحة، 500 لفشل غير متوقع. رقم الخطأ لا يصلح الخطأ؛ يساعد الواجهة على اختيار رسالة وسلوك مناسبين.
