# ٦ — الشاشات: ماذا ينفذ كل تفاعل؟

[الفهرس](README.md) · [التالي: أدوات البناء والتشغيل](07-tooling-and-running.md)

اقرئي الدوال أولًا ثم JSX. كثرة الأسطر في الشاشة لا تعني كثرة الخوارزميات؛ جزء كبير منها نصوص عربية وتنسيقات وخيارات الوصول. معجم الفصل الخامس يشرح كل خاصية تنسيق متكررة.

## Organizer.tsx: المكوّن الذي يجمع الرحلة

[الملف](../../src/screens/Organizer.tsx)، ٧٤٣ سطرًا. الأسطر ١–٥٥ استيرادات React وحاويات الهاتف ومشاركة الرابط والمناطق الآمنة والأيقونات والـAPI والـhook والمكونات والشاشات. لا يوجد تنفيذ خفي داخل أسطر import الخاصة بالأنواع. الأسطر ٥٧–٦٣ تعرّف نوع Tab محصورًا بأربع قيم وقائمة عنوان وأيقونة لكل تبويب؛ `as const` يحفظ القيم الحرفية للنوع.

### Logo، الأسطر ٦٥–٨٥

نص «حاتم» بالخط العربي ونقطة مرجانية صغيرة داخل Row. يُصدّر كي تستخدمه شاشة الدعوة أيضًا. هذه هوية مرسومة بعناصر، وليست تحميل صورة شعار إضافية.

### state والتحميل، الأسطر ٨٧–١٢٠

`useOrganizer` يعطي المجموعة وحالة تحميلها/حفظها وخطأها. بقية الحالة تخص الشاشة:

| المتغير | ماذا يمثل؟ |
|---|---|
| `catalog`, `catalogError` | قائمة التجارب وخطأ تحميلها المستقل |
| `tab` | التبويب الحالي، يبدأ discover |
| `detail` | التجربة المعروضة في ورقة التفاصيل أو null |
| `profile`, `invite` | ظهور ورقة التفضيلات أو الدعوة |
| `copied` | نجاح نسخ الرابط؛ effect يعيده false عندما تتغير حالة ورقة الدعوة |
| `remove` | العضو الجاري تأكيد إزالته أو null |
| `toast` | رسالة مؤقتة؛ مؤقت يمسحها بعد ٤٫٥ ثانية ويُنظَّف عند تغيّرها |
| `width`, `wide` | عرض النافذة؛ واسع عندما يبلغ ٩٠٠ |
| `insets` | حواف الجهاز الآمنة |
| `scroll` | مرجع ScrollView للعودة للأعلى عند تبديل التبويب |

`loadCatalog` تطلب api.catalog وتضع النتيجة أو رسالة فشل، وeffect يستدعيها أول مرة. استقلال خطأ الكتالوج عن خطأ المجموعة يجعل المستخدم قادرًا على إعادة تحميل التجارب دون إنشاء مجموعة جديدة.

### الأفعال، الأسطر ١٢١–١٧٨

`navigate(next)` تبدل tab وتعيد ScrollView إلى y=0 بلا حركة. لا تعيد تحميل الـAPI من أجل التنقل وحده. `update(settings)` تنتظر organizer.settings ثم تلتقط الفشل لأن الـhook قد وضع الرسالة الدائمة في الصفحة؛ لا تعرض نجاحًا وهميًا.

`save(e)` هو حفظ الجيب اليدوي. إن لم توجد group أو كان الحفظ جاريًا، تتوقف. إذا كانت التجربة ركيزة تطلب عبر toast اختيار ركيزة أخرى أولًا؛ وإذا كانت مكتملة تخبرك أنها في اللحظات. خلاف ذلك تفحص `settings.pocket_ids`، وتزيل المعرف بـfilter أو تضيفه لنسخة جديدة، ثم تحفظ جميع الإعدادات. عند نجاح الوعد تظهر رسالة مناسبة. `.catch(() => {})` هنا يمنع رفضًا غير معالج بعدما عرض hook الخطأ؛ ليس نمطًا لحذف الأخطاء بلا أثر في كل برنامج.

`inviteUrl` يركب العنوان العام ورمز الدعوة، دون مفتاح المنظّم. `copy` تستعمل Clipboard وتضع copied=true أو رسالة فشل. `share` تفتح Share الأصلية بنص ورابط؛ المستخدم يختار إلى من يرسل. فشل المشاركة يبقي خيار النسخ. هاتان الدالتان لا تنشئان مجموعة أو عضوًا جديدًا.

### أول تشغيل، الأسطر ١٨٠–٢٤٤

عند loading تظهر الهوية ومؤشر الانتظار. عند غياب group تظهر صورة وتعريف الفكرة وزر «نبدأ لَمّتنا». إذا كان الغياب بسبب خطأ استعادة، يظهر الخطأ وإعادة المحاولة بدل دفع المستخدم لإنشاء بديل دون تفسير.

زر البداية يفتح Sheet بنموذج emptyPreferences. onSave ينتظر `organizer.create(p)` ثم يغلق الورقة. لا توجد هنا شرائح onboarding متعددة أو تسجيل حساب؛ أول تفاعل فعلي هو تعبئة ذوق المنظّم وإنشاء المجموعة. النص التجريبي يوضح طبيعة البيانات.

### التنقل والمحتوى، الأسطر ٢٤٦–٤٨٥

`nav` شجرة JSX مشتركة. map يحول كل تبويب إلى Pressable مع أيقونة وعنوان وحالة selected. على الويب role=tab وعلى الهاتف button. تبويب الجيب يعرض شارة بعدد عناصر `group.plan.pocket`، الذي يشمل الجيب التلقائي واليدوي والممنوع.

في الصفحة الرئيسية SafeAreaView تحمي الأعلى. header يحوي الشعار والمدينة؛ المدينة نص ثابت «الرياض»، لا طلب GPS. التبويبات تظهر أعلى في الوضع الواسع، وأسفل داخل Glass في الهاتف. profile في الشريط الواسع يعرض أول حرف من الاسم ويفتح صفحة المجموعة؛ ليس حساب بريد مستقلًا.

ScrollView تحجز أسفل المحتوى مساحة كافية للشريط العائم وحافة الجهاز. أقصى العرض ١١٨٠ للاكتشاف والجيب و٧٨٠ للخطة والمجموعة. يظهر خطأ المجموعة أو الكتالوج مع فعل إعادة التحميل، ثم فرع التبويب:

| التبويب | ما يُمرر إليه؟ |
|---|---|
| discover | catalog/group، فتح التفاصيل، حفظ الجيب، الانتقال للخطة والمجموعة |
| plan | catalog/group/busy، تحديث Settings، فتح التفاصيل والجيب |
| group | group، فتح الدعوة، تعديل المنظّم، اختيار عضو لإزالته |
| pocket | يُرسم هنا مباشرة: empty state أو بطاقات من Plan.Pocket مع Notice لسبب كل عنصر |

في الجيب `catalog.find` يربط experience_id بالوصف والصورة. عند غيابه يعيد null ولا يرسم بطاقة ناقصة. البطاقات لا تحصل على onSave هنا؛ تعديل الحفظ يتم من التفاصيل. footer يشرح أن المحتوى توضيحي. toast فوق شريط التنقل، ويغلق عند الضغط عليه أو انتهاء مؤقته.

### أوراق التفاعل، الأسطر ٤٨٧–٦٥٦

**التفاصيل ٤٨٧–٥٧١:** visible من `!!detail`. تعرض صورة وتصنيفًا ومكانًا ووصفًا وسعرًا ودقائق وسببًا تحريريًا. إن كان العنصر ممنوعًا في الجيب تعرض سبب المنع. وإن كان مختارًا تعرض adaptations. `find(...)!` يأتي بعد فحص وجود العنصر في هذا السياق؛ علامة ! نفسها ليست تحققًا وقت التشغيل.

إذا لم تكن التجربة مكتملة يظهر فعل الركيزة: إن كانت الحالية يجعل anchor_id=null؛ وإلا يضع معرفها ويزيله من pocket_ids حتى لا يتعارضا. ينتظر نجاح الحفظ ثم يغلق التفاصيل وينتقل للخطة. زر الجيب يعكس الحفظ اليدوي ويُعطّل للركيزة أو وقت الحفظ. لا يحجز هذا الفعل موعدًا لدى مكان الطعام.

**تعديل الذوق ٥٧٢–٥٨٨:** يجد العضو ذي organizer=true ويستعمل PreferencesForm بقيمه. عند نجاح organizer.profile يغلق. بقية الأعضاء لا يُعدَّلون من هذه الورقة.

**الدعوة ٥٨٩–٦٣٠:** شرح الرحلة دون تثبيت التطبيق، رابط قابل للتحديد باتجاه ltr، زر نسخ تتغير أيقونته بعد النجاح، وزر مشاركة، ثم نص يوضح من يرى ماذا. الرابط يخص المجموعة، وليس نفقًا جديدًا لكل عضو.

**إزالة عضو ٦٣١–٦٥٣:** تعرض اسم العضو وأثر إزالته، وتنتظر organizer.remove قبل إغلاق التأكيد. لو فشل الحذف تبقى رسالة الخطأ في الحالة؛ لا تُحذف البطاقة محليًا قبل التأكيد من الخادم. يستطيع الشخص إعادة الانضمام بالدعوة، فهذه إزالة عضوية وليست قائمة حظر.

### الأنماط ٦٥٨–٧٤٣

`loading/welcome` يضبطان البداية، `header/headerContent/location/profile` الشريط العلوي، `tab/activeTab/badge` التبويبات وعدد الجيب، `bottomWrap/bottomNav` التثبيت العائم والزجاج، `footer/toast` النهاية والتنبيه. `Math.max(14, insets.bottom)` يحافظ على حد أدنى لمسافة الشريط عن أسفل الجهاز. كل بُعد/حد/لون يعود لمعجم التنسيق السابق.

## Discover.tsx: اكتشاف مختار وبحث محلي

[الملف](../../src/screens/Discover.tsx)، ٣٨١ سطرًا. الاستيرادات تجمع الصور والتدرج والأيقونات والمكونات. الدالة تستقبل catalog وgroup والأفعال؛ لا تحفظ إلى الشبكة بنفسها.

الأسطر ٤١–٥٣ تحدد wide، وحالة category الافتراضية «الكل» وsearch الفارغة. hero تبحث عن fire وإلا أول عنصر. filtered تشترط مطابقة التصنيف ووجود النص المدخل ضمن دمج العنوان والمكان والمطبخ والحي. `includes` بحث نصي بسيط بعد trim؛ لا يوجد بحث دلالي أو تصحيح إملائي أو تطبيع كامل للهمزات. pocketIds مجموعة من **كل الجيب الناتج** لتحديد شارة البطاقات.

بقية الرسم حتى السطر ٢٩٥ تتكون من:

1. مقدمة الفكرة وزر الخطة. wide يضعها بجانب صورة hero بدل فوقها.
2. صورة fire وتدرج يجعل النص فوقها مقروءًا ووسم زجاجي. العنوان والحي في hero مكتوبان لتجربة fire؛ fallback أول عنصر يحمي الغياب من الانهيار لكنه لا يجعل النص الترويجي ديناميكيًا بالكامل.
3. شريط المجموعة: أول ثلاثة أعضاء بأول حرف من الاسم، ألوان وصور رمزية متداخلة، وعدد الأعضاء والخانات، وضغطة لإدارة المجموعة.
4. عنوان قائمة التجارب والعدد الإجمالي، Chips للتصنيف وحقل بحث مضبوط بالقيمة.
5. grid من filtered: ثلاث أعمدة عند ٩٠٠ فأكثر، عمودان عند ٦٠٠ فأكثر، وعمود واحد دونها. البطاقة تأخذ priority من selected إن وجدت. `saved` هنا يشير إلى Plan.Pocket، بينما فعل الحفظ في Organizer يبدل Settings.PocketIds فقط؛ ظهور العلامة قد يكون بسبب الوقت أو قيد، وليس حفظًا يدويًا.
6. Empty عند صفر نتائج، ورسالة فلسفة الجيب في النهاية.

الأنماط ٢٩٧–٣٨١ تعرّف العنوان والصورة والشارة وتدرج طبقاتها، صور الأعضاء، الفلاتر والبحث، grid والخاتمة. لا تؤثر كثافة الأعمدة على ترتيب Planner أو سعة الخطة.

## PlanScreen.tsx: الخطة الناتجة وأسبابها

[الملف](../../src/screens/PlanScreen.tsx)، ٢٦٤ سطرًا. props هي group/catalog/update/busy/onOpen/onPocket. لا تحتوي useState؛ بياناتها من الأب، ومسودة الوقت داخل MealControl.

بعد المقدمة تمرر الخانات والمستهلك إلى MealControl. دالة onChange تحفظ `{...group.settings, slots}` كاملة. وجود anchor_issue يعرض نص المشكلة ومعه توضيح خانة الركيزة المحفوظة.

map على selected يربط كل Decision بتجربة. إن غابت التجربة لا يرسمها. البطاقة تميز الركيزة بلون وحد مختلفين، ثم تعرض الرتبة ورقم الخانة `consumed + index + 1` والعنوان والسعر والسبب. هذا الرقم ترتيب عرض؛ ليس موعدًا بتاريخ وساعة. adaptations تتحول إلى سطور مع أيقونة Leaf؛ النص نفسه قد يكون تحذير حرارة، فالأيقونة لا تعني حصرها بالنباتية.

«عشناها» تنادي update بإضافة المعرف إلى completed_ids مع نسخ باقي الإعدادات. الخادم يعيد الحساب، فتخرج التجربة من المختار ويزيد المستهلك. زر التفاصيل يفتح نفس الورقة التي تعرفنا عليها.

| الشرط | ما تعرضه الشاشة؟ |
|---|---|
| selected فارغة وavailable صفر | رسالة أن الخانات استُهلكت |
| selected فارغة وهناك سعة | رسالة مراجعة التوافق والركيزة |
| unfilled أكبر من صفر | عدد خانات لم نفرض تجربة لملئها |
| pocket غير فارغة | بطاقة تفتح الجيب بعدده |
| completed_ids غير فارغة | سجل اللحظات، وزر تراجع يزيل المعرف بـfilter ويحفظ |

التراجع يصحح تعليمًا عرضيًا، ولا يضيف تجربة مكررة إلى الكتالوج. `planCard/thumb/reason/pocket/completed` في الأنماط ٢٣٨–٢٦٤ تضبط البطاقات وصورها والفواصل.

## GroupScreen.tsx: صلاحيات المنظّم في الواجهة

[الملف](../../src/screens/GroupScreen.tsx)، ١٦٥ سطرًا. يستقبل group وonInvite وonEdit وonRemove. يعرض بطاقة دعوة وزرها، والعدد من ١٢، ثم map على members.

لكل عضو دائرة بحرف الاسم ولون من ثلاثة بـ`index % 3`، واسم وسياق الإقامة والميزانية. العضو المنظّم يظهر معه «أنت · المنظّم» وزر Edit الذي يستدعي onEdit. غيره يظهر معه Trash الذي يمرر العضو كاملًا إلى onRemove لورقة التأكيد. تبقى الصلاحية الحقيقية في API، لا في هذا الشرط وحده.

تفضيلات المطابخ Chips، والنباتي وغير الحار يظهران عند true، والحساسيات تظهر إن كانت القائمة غير فارغة. ذلك مسموح في GroupView للمنظّم، وليس InviteView العامة. لا توجد هنا دعوة SMS تلقائية ولا صور حسابات مرفوعة. الأنماط ١٣٤–١٦٥ تضبط بطاقة الدعوة وأيقونتها وبطاقة العضو وصورته الرمزية.

## InviteScreen.tsx: العضو من المتصفح

[الملف](../../src/screens/InviteScreen.tsx)، ٣١٢ سطرًا. هذه رحلة مستقلة عن واجهة إدارة المنظّم، وتستخدم مكونات العرض والنموذج نفسها.

### الأسطر ٢٦–٦٦: الحالة والتحميل

تحفظ invite وcatalog وmember وtoken وحالات loading/error/edit/busy/saved. loading يبدأ true فقط إذا وُجد code. `load` تستعمل useCallback باعتماد code، وتتوقف إن غاب. تشغل ثلاثة أعمال مستقلة بـPromise.all: قراءة الدعوة، قراءة الكتالوج، وقراءة مفتاح العضو من التخزين باسم `hatim.member.${code}`. تضمين code يمنع اختلاط مفاتيح دعوتين في نفس المتصفح.

إن وجد مفتاح تحاول Me. 404 يحذف المفتاح المحلي غير الصالح؛ خطأ اتصال آخر يُعاد لمسار الخطأ. finally ينهي loading. effect ينادي load عند بدء الشاشة أو تغير code.

### الأسطر ٦٧–١٠٣: polling

بعد وجود code ودعوة، يبدأ مؤقت ٦ ثوانٍ. يتخطى busy أو fetching، ثم يقرأ الدعوة ويحدثها ما دام alive. إن يوجد token، يقرأ ملف العضو أيضًا. 404 هنا يفرغ member/token ويحذف التخزين؛ مثل حالة إزالة المنظّم لهذا العضو. فشل قراءة الدعوة يظهر error. finally ينهي fetching، وcleanup يمسح المؤقت ويمنع تحديث state بعد انتهاء دورة effect.

اعتمادات effect تشمل code ووجود invite وtoken وbusy. وجود `!!invite` بدل الكائن كاملًا يمنع إعادة إنشاء المؤقت لمجرد كل رد جديد. هذه الشاشة لا تستخدم epoch الخاص بالمنظّم، ولا تضيف منطق AppState نفسه. اشرحي الموجود كما هو، ولا تفترضي أن كل hook مشترك بين الشاشتين.

### save، الأسطر ١٠٤–١٢٨

إن كان لدينا token تعدّل Me؛ وإلا تنضم كعضو جديد ثم تحفظ member_token محليًا وتضع بيانات العضو. بعد نجاح حفظ الملف تضع saved=true وتغلق الورقة، وتحاول إعادة قراءة العرض المشترك. لو نجح الحفظ وفشلت القراءة، تعرض خطأ تحديث العرض بدل إعادة الانضمام وإنشاء عضو ثانٍ. finally تعيد busy=false. فشل الحفظ الأساسي يصعد إلى PreferencesForm التي تعرض الخطأ ولا تعتبره نجاحًا.

### الرسم، الأسطر ١٢٩–٢٨٤

| الحالة | النتيجة |
|---|---|
| loading | مؤشر انتظار |
| لا code | صفحة تطلب فتح رابط من المنظّم، وليست نموذج إنشاء مجموعة |
| code لكن لا invite | رسالة فشل مع زر إعادة load |
| invite موجودة | ترحيب، أسماء المجموعة، الخانات، نموذج الانضمام أو التعديل، والخطة المشتركة |

وجود member يغير الترحيب والزر إلى تعديل الذوق. saved يظهر رسالة تأكيد. الخطة تعرض priority والعنوان والحي والسعر والسبب العام لكل تجربة. لا يوجد فيها تعديل الركيزة أو الوقت أو حذف عضو. إذا كانت selected فارغة، تميز بين استهلاك الخانات ومراجعة التوافق. anchor_issue العامة تظهر إن وجدت.

Sheet في نهاية الشجرة تستقبل ملف العضو أو emptyPreferences وتسند onSave إلى save. نص الزر يتغير حسب الانضمام أو التعديل. الأنماط ٢٨٥–٣١٢ تضبط عرضًا أقصى ٥٩٠، صورة المقدمة، شريط الأشخاص ودائرة الأيقونة وبطاقات الخطة. footer يوضح البيانات التوضيحية.

## تمارين الربط

ابدئي من زر «أضيف ذوقي للَمّة» وارسمي سلسلة الدوال حتى INSERT. ثم ابدئي من «عشناها» حتى خروج التجربة من Plan.Selected. وأخيرًا اقطعي الاتصال في بيئة تدريب: يجب أن تعرفي أي Notice ستظهر، وأي بيانات محفوظة لا ينبغي محوها. القدرة على تتبع فعل واحد عبر الملفات أهم من حفظ ترتيب الاستيرادات.
