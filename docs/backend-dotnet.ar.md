# باك إند حاتم باستخدام .NET

هذه هي النسخة الحالية بعد نقل الباك إند من Python إلى C# وASP.NET Core 10. واجهة React Native وExpo بقيت كما هي. ملفات `docs/learning/` القديمة تشرح نسخة Python التاريخية؛ استخدمي هذا الملف لأوامر الباك إند الحالية.

## كيف تشغّلينه؟

من مجلد المشروع، بعد تثبيت .NET 10 SDK وNode:

```sh
npm ci
dotnet restore backend/Hatim.slnx
npm run api
```

الخادم يعمل على `http://127.0.0.1:8000`. افتحي `/api/health` للتأكد من عمله؛ ستظهر قيمة `backend` مساوية لـ`dotnet`.

لتشغيل السيميوليتر، افتحي نافذة Terminal ثانية:

```sh
npm run ios:release
```

السيميوليتر يتصل مباشرة بالخادم الموجود على الماك. لتجربة الأعضاء من المتصفح شغّلي:

```sh
npm run public:test
```

هذا الأمر يبني الباك إند والواجهة، ويشغّل نفق Cloudflare. إن كان خادم .NET يعمل بالفعل، يستخدمه. إذا كان المنفذ مشغولًا بخادم Python القديم، أوقفيه أولًا. اتركي نافذة التشغيل مفتوحة. الرابط مؤقت ويتغيّر عند إعادة تشغيل النفق؛ أعيدي بناء تطبيق الآيفون لتحديث رابط الدعوة والاتصال من جهاز حقيقي.

## أين يوجد كل جزء؟

| الملف | مسؤوليته |
| --- | --- |
| `backend/Hatim.Api/Program.cs` | نقطة تشغيل الخادم: إعداد JSON، ربط الخدمات، سياسة الطلبات، المسارات وملفات الويب. |
| `backend/Hatim.Api/ApiController.cs` | استقبال طلبات إنشاء المجموعة، تعديل الخطة والملفات، الانضمام وعرض الدعوة. |
| `backend/Hatim.Api/Models.cs` | أشكال البيانات، الحقول المطلوبة، القيم المسموحة، وقواعد صحة الإعدادات. |
| `backend/Hatim.Api/Planner.cs` | محرك القرار: القيود، التعديلات الممكنة، النقاط، الأولويات، والخطة والجيب. |
| `backend/Hatim.Api/Store.cs` | قراءة وكتابة SQLite باستخدام SQL بمعاملات، وحساب بصمات رموز الوصول. |
| `backend/Hatim.Api/catalog.json` | التجارب التحريرية التوضيحية التسع، بنفس بيانات النسخة السابقة. |
| `backend/Hatim.Api.Tests/` | اختبارات المنطق، واجهات HTTP، وتوافق البيانات القديمة. |
| `backend/Hatim.slnx` | يجمع مشروع الخادم ومشروع الاختبارات. |

## مثال: ماذا يحدث عندما تضغطين «نبدأ اللَمّة»؟

1. `PreferencesForm` في تطبيق React Native يجمع اسمك وذوقك وقيودك.
2. `src/api/client.ts` يرسل طلب `POST /api/groups` ويضع البيانات في جسم الطلب بصيغة JSON.
3. ASP.NET Core يحوّل JSON إلى كائن `CreateGroup` ويفحص الحقول. يرفض البيانات غير الصحيحة بالحالة `422`.
4. `ApiController.Create` ينشئ معرّف المجموعة ورمز المنظّم ورمز الدعوة باستخدام مولّد عشوائي آمن.
5. `Store.Run` يفتح اتصالًا بقاعدة البيانات ويبدأ معاملة. المعاملة تجعل إنشاء المجموعة والمنظّم عملية واحدة: تنجح كلها أو تتراجع كلها عند فشلها.
6. قاعدة البيانات تحفظ بصمة SHA-256 لرمز المنظّم. الرمز نفسه يُرجع للتطبيق مرة الإنشاء، ويحفظه التطبيق في SecureStore.
7. `Planner.Build` يحسب الخطة، ثم الخادم يرجع المجموعة والخطة والرمز بالحالة `201`.
8. React Native يعرض شاشة الاكتشاف. الطلبات اللاحقة ترسل الرمز في ترويسة `Authorization: Bearer ...`.

## كيف تعرّفين البيانات في C#؟

`record` يعرّف شكل بيانات، و`string` يعني نصًا، و`int` عددًا صحيحًا، و`bool` قيمة صحيحة أو خاطئة. الرمز `?` يسمح للقيمة بأن تكون `null`، و`[]` يعني مجموعة عناصر.

مثلًا، `Settings.Slots` يمثل عدد خانات الوجبات. `[Range(1, 9)]` يفرض أن العدد من ١ إلى ٩. قواعد `IValidatableObject` تفحص العلاقات بين الحقول: لا يمكن أن تكون التجربة في الجيب ومكتملة في الوقت نفسه، ولا يمكن تقليل الخانات إلى أقل من عدد الوجبات المستهلكة.

`enum` يحدد مجموعة قيم معروفة، مثل أنواع المطابخ. أسماء C# داخل الكود إنجليزية، بينما `JsonStringEnumMemberName` يحدد القيمة العربية التي يرسلها الخادم ويستقبلها. وهكذا تستمر الواجهة الحالية في إرسال «سعودي» و«مقيم» مثل السابق.

`ApiJson` يوحّد تحويل البيانات: الخاصية `InviteCode` في C# تظهر كـ`invite_code` في JSON، وتزيل النماذج المسافات من أطراف الاسم والعنوان ومعرّفات التجارب المدخلة. الحقول غير المعروفة تُرفض بدل تجاهلها.

## كيف تُرتَّب التجارب؟

`Evaluate` تفحص تجربة واحدة مقابل جميع الأعضاء. الحساسية غير الموثقة والميزانية قيود صلبة. التفضيلات المرنة قد تحصل على تعديل واضح أو تقلل نقاط التوافق. ثم تُضاف نقاط التوافق إلى التقييم التحريري: ٧٠٪ لمتوسط توافق الأعضاء و٣٠٪ لأقلهم توافقًا.

`Build` تمر على التجارب، تستبعد المكتملة من الفرص المستقبلية، وتحفظ ما وُضع يدويًا في الجيب. ترتّب المرشحين مع تقديم الركيزة. عندما يقل الوقت، تأخذ مقدمة القائمة نفسها. إذا تعذرت الركيزة تحجز خانتها وتشرح السبب. الباقي يذهب للجيب.

هذه الدوال لا تتصل بقاعدة البيانات أو الإنترنت. لذلك يمكن اختبارها مباشرة بمدخلات معروفة والتأكد من مخرجاتها.

## ماذا حدث للبيانات القديمة؟

الخادم يستخدم الملف نفسه: `backend/data/hatim.sqlite3`. بقيت الجداول وأسماء الأعمدة وترتيب الأعضاء وبصمات الرموز ورموز الدعوة متوافقة. لا تحتاجين إنشاء المجموعات السابقة مرة ثانية، ولا تحتاج نسخة iOS لإعادة تسجيل الدخول بسبب تغيير لغة الخادم.

قبل التحويل أُخذت نسخة احتياطية محلية في `.run/migration/pre-dotnet.sqlite3`. قاعدة البيانات والنسخ الاحتياطية غير مرفوعة إلى GitHub.

## الاختبارات وتوليد الأنواع

```sh
npm run check
npm run format:api:check
npm run types:api
npm run typecheck
```

`npm run test:api` يشغّل اختبارات xUnit. يتضمن ١٨٠ حالة محفوظة من مخرجات Python الأصلية للمقارنة، واختبارات لصلاحيات الوصول، خصوصية الدعوات، الإدخال غير الصحيح، الانضمام المتزامن، والبيانات القديمة. تستخدم الاختبارات قواعد بيانات مؤقتة.

`npm run types:api` يبني الخادم ويشغّل نسخة مؤقتة منه على منفذ محلي متاح تلقائيًا وبقاعدة مؤقتة. يأخذ مستند OpenAPI ويولّد منه `src/api/schema.d.ts`، ثم يوقف النسخة المؤقتة. لا يعدّل مجموعتك أثناء توليد الأنواع.

اختبارات المتصفح تُشغّل بـ`npm run test:e2e` عندما تكون واجهة الويب والخادم جاهزين. استخدمي قاعدة اختبار مستقلة عبر `HATIM_DB` عند تشغيل اختبار ينشئ مجموعات. إعداد `HATIM_TEST_URL` يوجه Playwright إلى عنوان خادم الاختبار.
