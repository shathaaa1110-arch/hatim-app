# عقد القرار السريع وتفضيلات الطلعة

منفذ في 24 سبتمبر 2026. المصدر الدقيق: [OpenAPI](../backend/openapi.json). [شرح المبتدئة](learning-python-postgres/18-quick-decision.ar.md).

## بحث بلا حفظ

`POST /api/quick-decisions` عام، لا يحتاج حسابًا. لا ينشئ خطة أو عضوية ولا يخزن التفضيلات المرسلة. الخادم يقرأ الكتالوج في معاملة للقراءة فقط ثم يستعمل نفس محرك القيود. الواجهة تمرر ذوق المستخدم الجديد أو تفضيلات جميع رفقة خطته المباشرة الحالية التي يملك حق قراءتها. هذا ليس مدخلًا للبحث عن بيانات أعضاء آخرين، ولا يستقبل group_id لقراءة خطتهم.

```json
{
  "members": [{"name": "أمل", "budget": 150, "allergies": [], "vegetarian": false}],
  "minutes": 60,
  "neighborhood": null,
  "context": {"kind": "family", "priorities": ["quiet", "sharing"]},
  "excluded_ids": ["coffee"]
}
```

members: من1 إلى12، وكل عنصر Preferences الحالي. minutes: عدد صحيح15–240، مدة التجربة وحدها بعد خصم الطريق والانتظار يدويًا. neighborhood: null لكل الأحياء أو نص1–60 بمطابقة تامة؛ حي غير موجود ينتج قائمة فارغة ولا يوسع البحث خفية. excluded_ids: حتى30، تستعملها الواجهة لاستثناء المكتمل والجيب اليدوي. لا حاجة لإرجاع خطأ لمعرف مستثنى غير موجود.

الرد200 هو `{choices: Decision[], message, duration_note}`. choices من0 إلى3؛ سبب كل اختيار يشرح ملاءمة المدة والتفضيلات والتعديلات الغذائية إن وجدت. لا تعني priority هنا خانة محفوظة؛ الحفظ خطوة صريحة لاحقة. عدم وجود نتيجة يميز بين عدم وجود تجربة بالوقت/الحي وبين تعارض القيود. لا يجري الطلب كتابة، وتطبق سياسة no-store وحد الجسم16KB و422 للتحقق و503 لتعذر قاعدة البيانات. لا سجلات بحث أو جدول جديد.

## تفضيلات خاصة بخطة أو طلعة

`Settings.context` و`OutingCreate.context` يستعملان الشكل نفسه:

- kind: `any` أو `family` أو `friends`، افتراضيًا any.
- priorities: من0 إلى3 قيم فريدة من `quiet/sharing/discovery`، افتراضيًا [].

واجهة الاختيار تقترح family→quiet+sharing وfriends→sharing+discovery، ثم يستطيع المستخدم تعديلها. الخادم يحفظ القيم الصريحة؛ إرسال kind وحده لا يفترض تفضيلات أو وجود أطفال.

`Experience.outing_traits` خصائص تحريرية بالقيم نفسها. يضيف المحرك8 نقاط لكل أولوية متطابقة بعد اجتياز قيود كل شخص، ويكتب السبب. لا يستبعد تجربة لمجرد غياب الصفة، ولا يغير أولوية الركيزة، ولا يستنتج مرافق أطفال أو خصوصية من kind. بيانات التجارب التسع وهمية، ومنها الصفات، ولا توجد ساعات فتح أو مسافة أو زحام مباشر.

الخطط: POST /api/groups يحفظ context ضمن settings؛ PUT /api/groups/{id}/settings يحفظها مع expected المعتاد. GET /api/invites/{code} يعرض context وسبب توافقها العام دون كشف تفضيلات الأشخاص أو تعديلاتهم الخاصة. إنشاء خطة من نتيجة سريعة يستعمل POST الحالي، settings.slots=1 وanchor_id المختار. اعتماد نتيجة لخطة موجودة يستعمل PUT الحالي بعد تأكيد استبدال الركيزة؛ تبقى الخانات والمكتمل والجيب.

القروبات: POST /api/v2/groups/{id}/outings يقبل context؛ PUT /api/v2/outings/{id}/settings يخضع لمالك القروب أو القائد والتحقق من expected. تغيير context يبطل الجولة ويرفع planning_revision مرة، أما تغيير الخانات وحدها فلا يفعل. إغلاق الطلعة يحفظ إعداداتها ولقطة الخطة كما كانت. تغيير context لا يعدل circle_members.preferences أو ميزانية الأشخاص. التحويل القديم إلى قروب ينقل settings كاملة ومنها context.

القراءة القديمة لبيانات بلا context ترجع القيم المحايدة. قائمة الصفات القديمة بلا outing_traits ترجع []. الترحيل004 يضيف صفات للكتالوج الوهمي فقط حين الحقل غير موجود، ولا يعيد كتابة الترحيلات السابقة أو يمس الجداول الشخصية.

العميل المباشر القديم الذي يغفل context في PUT يحافظ على السياق المخزن. إذا أرسل expected قديمًا يخالف السياق الحالي يرجع409 المعتاد. الواجهة تمنع اعتماد نتيجة سريعة على خطة استهلكت كل خاناتها؛ تزيد المستخدمة الخانات أو تبدأ خطة جديدة بنفسها، فلا تعود خانة مستهلكة تلقائيًا.
