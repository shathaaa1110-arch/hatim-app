# 10 · كيف تعرفين أن الكود صحيح؟

[الفهرس](README.ar.md) · [التالي: استكمال نسخة المدرسة](11-school-build.ar.md)

الاختبار يجهز مدخلات، ينفذ فعلًا، ويقارن بنتيجة متوقعة كتبناها من المتطلبات. `assert` في pytest يوقف الاختبار إن لم يتحقق الشرط. فشل الاختبار معلومة تساعدك؛ تغيير التوقع حتى يوافق خطأ التنفيذ لا يصلح المنتج.

## الاختبارات الموجودة

| الملف | ماذا يثبت؟ |
|---|---|
| test_planner.py | التقلص كمقدمة ثابتة، التعامل مع القيود والركيزة والجيب والمكتمل وعدم تأثر الترتيب بترتيب الأعضاء |
| test_api.py | انضمام العضو، تحديثه، عزل المجموعات، خصوصية الدعوة، إزالة عضو وإبطال مفتاحه، حد المجموعة والحفظ |
| test_postgres.py | صحة اتصال DB، الانضمام المتزامن، rollback ولقطة القراءة، الترحيلات، النقل الآمن، المدخلات الصارمة، حجم الجسم وCORS وعقد الخطأ |
| conftest.py | تجهيز DB معزولة وTestClient والتنظيف لكل اختبار |
| group-flow.spec.ts | رحلة متصفحين، تقليص الخطة وتفضيلات العضو وإكمال/تراجع والبحث والجيب وإعادة المحاولة وحجم الشاشة |

test_planner تستعمل 180 حالة بيانات محفوظة للتحقق من بقاء قرارات النسخة السابقة. هذه حالات regression، لا إثبات وحدها أن التصميم مثالي؛ لذلك توجد اختبارات متطلبات مستقلة أيضًا. ملف planner-parity.json بيانات: members وsettings وplan، وليس خوارزمية AI أو سجلات أشخاص حقيقيين.

test_api.create دالة مساعدة تصنع مجموعة اختبار وتعيدها مع رأس Authorization. إعادة الاستخدام تقلل التكرار ولا تستبدل التوقعات. underscore `_` في `group, _` يعني أننا لا نحتاج المتغير الثاني في هذا الموضع.

## PostgreSQL فعلية أثناء الاختبار

fixture database تقرأ HATIM_TEST_DATABASE_URL أو DATABASE_URL، تنشئ schema عشوائية باسم hatim_test_...، وتضبط search_path لها داخل اتصال التطبيق. تشغّل initialize، ثم yield إلى الاختبار، وفي finally تحذف فقط schema التي أنشأتها. لا تمسح public ولا جداول المستخدمين. `monkeypatch` تغيير مؤقت للبيئة يعيده pytest بعد الاختبار.

fixture client تعتمد على database، وتدخل TestClient في سياق ليعمل lifespan. هذه طلبات داخل عملية الاختبار إلى FastAPI، لا تحتاج Uvicorn على 8000؛ لكن psycopg تتصل بخادم PostgreSQL الحقيقي. مكتبة httpx2 مستعملة في عميل اختبار Starlette في الإصدارات المقفلة.

اختبار concurrent joins يبدأ 16 محاولة مع مجموعة فيها المنظّم: نتوقع 11 إنشاءً و5 ردود 409، والعدد النهائي 12. بدون القفل قد يقرأ أكثر من طلب العدد نفسه ويدخلون معًا. هذا اختبار قاعدة عمل، لا مجرد مقارنة اسم الدالة بما نريد.

اختبار snapshot يفتح قارئًا، يضيف صفًا من اتصال آخر، ويثبت أن القارئ ما زال يرى لقطته القديمة، بينما اتصال قراءة جديد يرى الصف. اختبار import يستعمل SQLite مصطنعة في tmp_path، لا بياناتك، ويتحقق من صلاحية مفاتيحها بعد النقل ومن رفض الكتابة فوق وجهة مستخدمة.

## Playwright

`test` حالة اختبار، `expect` توقع قد يعاد التحقق منه حتى مهلة مناسبة، وpage تمثل تبويبًا. getByRole يعتمد اسمًا ودورًا قابلين للوصول بدل إحداثيات بكسلات. browser.newContext يصنع بيئة مستقلة بتخزين خاص للعضو، فلا يرث مفتاح المنظم. request يستخدم API داخل نفس السيناريو للتحقق مما حفظته الواجهة.

اختبار retry يعترض رد الدعوة أولًا بـ503، ثم يزيل الاعتراض ويضغط إعادة المحاولة. اختبار الرحلة ينتظر رد POST قبل قراءة المفتاح، ويختبر تحديث المنظم بعد polling، ويتأكد ألا تظهر كلمة الحساسية في JSON العامة. يأخذ screenshots ويفحص عدم تجاوز عرض الصفحة شاشة صغيرة. هذه اختبارات web وليست إثباتًا لاجتياز كل إصدارات iOS أو قارئ الشاشة.

playwright.config يحدد testDir و60 ثانية للحالة وtrace عند الفشل وصورة عند الفشل، ومتصفح Chromium وviewport. عنوانه الافتراضي 8000، **واختبارات المتصفح تنشئ بيانات فيه**. استخدمي API اختبار منفصلة على 8002 وقاعدة/مخطط مخصص، لا خدمة المجموعات الشخصية الحالية.

## أوامر التحقق

```sh
npm run typecheck
npm run test:api
npm run format:check
uv run --project backend ruff check backend
uv run --project backend ruff format --check backend
```

ولخدمة اختبار web منفصلة مبنية ومشغلة مسبقًا على 8002:

```sh
HATIM_TEST_URL=http://127.0.0.1:8002 npm run test:e2e
```

في التحقق السابق للنسخة 59d45d3 نجحت 223 حالة pytest و3 حالات متصفح، وبُنيت نسخة iOS Release وشُغلت على المحاكي. هذا وصف تحقق النموذج السابق، وليس نتيجة تشغيل اختبارات جديدة في جلسة كتابة الدليل ولا ضمانًا لعدم وجود أي عيب. بقي تحذير deprecation من Starlette/AnyIO وبعض تحذيرات حزم البناء؛ لا تغيّري مكتبات مورّدة لمجرد إسكاتها.

## حين يقول التطبيق: ما قدرنا نتصل

| ما تلاحظينه | ماذا تفحصين؟ |
|---|---|
| localhost:8000 لا يرد | هل عملية Python تعمل؟ هل المنفذ مشغول بخدمة أخرى؟ |
| health ترجع 503 | PostgreSQL، DATABASE_URL في بيئة الخادم، و`npm run db:status` |
| الآيفون يفشل والمحاكي يعمل | العنوان العام داخل Release، صلاحية النفق، وبقاء الماك مستيقظًا |
| صفحة الدعوة لا تُفتح | domain مؤقت منتهي، أو رمز غير صالح، أو dist لم تُبنَ قبل تشغيل الخادم |
| 422 بعد تحريك قيمة | هل أرسلت رقمًا صحيحًا؟ هل الحقول متسقة؟ |
| 404 لمجموعة موجودة | هل تستعملين مفتاح منظّمها الصحيح؟ 404 هنا قد تعني صلاحية غير صحيحة |
| تغيير لا يظهر فورًا | هل الحفظ نجح؟ هل مرّت دورة polling؟ هل يوجد خطأ ظاهر؟ |
| تظهر شاشة البداية مجددًا | هل المفتاح المحلي غائب/غير صالح أو تغير المتصفح/النطاق؟ |

ابدئي بطبقة واحدة وافحصي الدليل قبل القفز للأخرى. لا تحذفي DB أو تمسحي المحاكي كأول حل لانقطاع شبكة.
