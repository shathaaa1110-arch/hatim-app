# 04 · الخادم من المدخل إلى الرد

[الفهرس](README.ar.md) · [التالي: محرك القرار](05-planner.ar.md)

Uvicorn يستقبل اتصال HTTP ويشغّل تطبيق ASGI. FastAPI يحدد المسار المطلوب، ويقرأ المدخلات، ويستدعي الدالة المناسبة. دوال المسارات المتزامنة هنا تستخدم psycopg المتزامنة؛ مجرد وجود async في lifespan لا يجعل استعلاماتنا غير متزامنة.

## models.py: عقد البيانات

المرجع: [الكود مع شرح مقاطعه](code/backend-hatim-models.py.ar.md).

`Literal` قائمة قيم مسموحة؛ المطبخ لا يقبل أي نص اعتباطي. `Model` يرث BaseModel ويمنع الحقول الزائدة، ويزيل الفراغات الطرفية من النصوص، ويطلب أنواعًا صارمة. يرفض slots كنص وvegetarian كنص. `Field` يضيف قيمة افتراضية أو حدودًا. `default_factory=list` يصنع قائمة افتراضية لكل نموذج.

| النموذج | ماذا يمثل؟ |
|---|---|
| ErrorResponse | رد خطأ فيه detail نصية؛ موثّق للـ422 |
| Preferences | الاسم 1–30 حرفًا، مقيم/زائر، المطابخ، الحساسية، نباتي، بدون حار، ميزانية 30–500 |
| Member | id، تفضيلات، وعلم organizer |
| Experience | الاسم والمكان والوصف والمطبخ والصورة والسعر والدقائق والنقاط والخيارات والمواد الحساسة |
| Settings | 1–9 خانات، ركيزة افتراضية fire، جيب يدوي، وتجارب مكتملة |
| Decision | تجربة مختارة، رتبة، سبب، تعديلات، نقاط |
| PocketItem | تجربة خارج الخطة وسبب خروجها وهل هي ممنوعة |
| Plan | المختار والجيب ومشكلة الركيزة والمستهلك والمتبقي وغير المملوء |
| CreateGroup | عنوان افتراضي وتفضيلات المنظّم |
| GroupView | بيانات الإدارة: المجموعة وأعضاؤها وإعداداتها والخطة |
| GroupCreated | GroupView ومفتاح المنظّم الخام وقت الإنشاء |
| MemberCreated | العضو ومفتاحه الخام وقت الانضمام |
| InviteView | عنوان وأسماء وخطة مختصرة؛ لا ملفات تفضيلات الآخرين |

`role` في Preferences تعني مقيمًا أو زائرًا؛ ليست دور إدارة. `organizer` هو العلم المختلف. `image` مفتاح مثل fire يجد به العميل صورة محلية. `minutes` معلومة عرض، ولا تستخدمها خوارزمية السعة؛ الخوارزمية تعد الخانات.

`Settings.coherent` يعمل بعد تحقق الحقول. يمنع تكرار completed_ids وpocket_ids، وأن تكون الخانات أقل من المكتمل، وأن تكون الركيزة في الجيب، وأن تكون تجربة مكتملة ومحفوظة يدويًا معًا، وأن تكون معرفات القوائم فارغة. ثم يعيد self. صلاحية معرف التجربة داخل الكتالوج تفحص لاحقًا في update_settings؛ حدود الأنواع وحدها لا تكفي.

`model_validate` يحوّل كائن Python إلى نموذج مفحوص، و`model_validate_json` يقرأ نص JSON ويفحصه، و`model_dump` يعيد قاموسًا. `Jsonb(...)` يجهز القيمة لPostgreSQL. `model_copy(update=...)` ينشئ نسخة مع تعديلات داخلية؛ ليس مسار تحقق لمدخلات المستخدم.

## main.py: بداية التشغيل

imports تجمع الأدوات والنماذج. `lifespan` ينفّذ initialize قبل قبول الطلبات. `app = FastAPI(...)` يحدد اسم الخدمة ومسار Swagger `/api/docs` وعقدها `/api/openapi.json`. البيانات هناك وصف للمسارات، وليست برنامج قاعدة بيانات.

CORS يحدد أي origins لمتصفح التطوير يسمح لها بقراءة الرد. صفحة الدعوة المبنية تتصل بنفس origin، فلا تحتاج فتح CORS للجميع. CORS لا يصادق على الأشخاص ولا يمنع عميلًا غير متصفح؛ مفاتيح الوصول وفحوص الملكية هي المسؤولة عن ذلك.

invalid_request يبدل تفاصيل أخطاء Pydantic برسالة عربية عامة 422. database_unavailable يسجل اسم نوع خطأ DB دون بيانات الاتصال، ويرجع 503. هذا ليس وعدًا بأن كل خطأ برمجي غير متوقع سيعيد نفس JSON؛ العميل أيضًا يتعامل مع 5xx عامة.

## المفاتيح الثلاثة

| القيمة | تصل إلى من؟ | ماذا تسمح؟ |
|---|---|---|
| invite_code | كل من يملك رابط الدعوة | قراءة النسخة العامة والانضمام إذا لم تمتلئ المجموعة |
| organizer_token | منشئ المجموعة، ويحفظه العميل | قراءة المجموعة الخاصة وتعديل الإعدادات وملفه وإزالة الأعضاء |
| member_token | العضو عند الانضمام، ويحفظه متصفحه | قراءة وتعديل ملفه فقط ضمن دعوته |

الخادم يولدها بواسطة secrets، ويخزن بصمات مفاتيح الإدارة والتعديل بـSHA-256. الرمز العشوائي الطويل مختلف عن كلمة مرور يختارها إنسان؛ SHA-256 هنا ليست وصفة لتخزين كلمات المرور. رمز الدعوة نفسه محفوظ بنصه لأنه جزء من البحث والرابط. لا تظهري مفتاح الإدارة في URL.

`bearer` يزيل بادئة Bearer إذا كانت صحيحة؛ بخلافها يعيد نصًا فارغًا. `require_owner` يبحث عن id وبصمة مفتاحهما معًا، و`require_member` يربط الدعوة ثم يفحص group_id وبصمة العضو وorganizer=false. عدم التطابق يرجع 404 حتى لا يعرض وجود المورد لمن لا يملك مفتاحه.

لا توجد هنا حسابات كلمات مرور أو انتهاء جلسات أو logout يلغيه الخادم أو استعادة حساب. من يفقد التخزين المحلي قد يفقد القدرة على إدارة مجموعته أو ملفه. تغيّر نطاق Cloudflare لا ينقل تخزين متصفح عضو من النطاق السابق، حتى لو بقي رمز الدعوة صالحًا في DB.

## كل endpoint حالي

| الطريقة والمسار | المدخل والصلاحية | العمل والنتيجة |
|---|---|---|
| GET /api/health | لا مفتاح | SELECT 1 حقيقي؛ حالة Python/PostgreSQL |
| GET /api/experiences | لا مفتاح | يعيد CATALOG الثابتة؛ لا يقرأ جدول تجارب |
| POST /api/groups | CreateGroup | يولد المعرفات، يحفظ المجموعة والمنظّم معًا؛ 201 وGroupCreated |
| GET /api/groups/{group_id} | مفتاح منظّم | قراءة متسقة وGroupView مع حساب الخطة |
| PUT /api/groups/{group_id}/settings | Settings ومفتاح منظّم | تحقق ids، قفل، استبدال الإعدادات، خطة جديدة |
| PUT /api/groups/{group_id}/profile | Preferences ومفتاح منظّم | يحدث صف organizer فقط ويعيد المجموعة |
| DELETE /api/groups/{group_id}/members/{member_id} | مفتاح منظّم | يحذف عضوًا غير منظّم من نفس المجموعة؛ يرفض غير ذلك |
| GET /api/invites/{code} | رمز دعوة | نسخة عامة مختصرة من الخطة |
| POST /api/invites/{code}/members | Preferences | يقفل المجموعة ويعد الأعضاء ثم ينضم؛ 201 أو 409 |
| GET /api/invites/{code}/me | مفتاح العضو | ملف صاحب المفتاح فقط |
| PUT /api/invites/{code}/me | Preferences ومفتاح العضو | تحديث ذلك الملف فقط |

PUT هنا ليس patch جزئية: إرسال `{"slots":1}` وحده ينشئ Settings ببقية الافتراضيات، ثم يستبدل الملف القديم. لذلك الواجهة ترسل `{...group.settings, slots}`. لا تفترضي أن كل حقل غائب سيبقى كما هو في DB.

## إنشاء مجموعة، سطرًا وراء معنى

افتحي [main.py المشروح](code/backend-hatim-main.py.ar.md) عند create_group. decorator يربط POST بالدالة ويحدد 201. `body: CreateGroup` يطلب نموذجًا صالحًا قبل دخول الدالة. توليد secrets يعطي group_id ومفتاح إدارة ورمز دعوة مستقلين. الاتصال الواحد يشمل INSERT للمجموعة وINSERT للمنظّم. preferences تحفظ بـJsonb. صف المنظّم له token_hash عشوائية لا تعاد؛ لا يستخدم مسار العضو، لأن تعديل المنظم يتم بمفتاح المجموعة. `require_owner` يعيد الصف، و`group_model` يبني الرد ويحسب الخطة. الخروج الناجح من المعاملة يثبت الصفين، ثم يرسل الرد.

`group_model` يقرأ أعضاء المجموعة بترتيب ثابت، و`member_model` يحذف عمليًا حقول DB غير المطلوبة من شكل الرد، مثل token_hash. بعدها يحول settings ويمرر الكتالوج والأعضاء والإعدادات إلى planner. لا يوجد جدول plans؛ النتيجة مشتقة عند كل طلب.

## الخصوصية في الدعوة

إخفاء النص في الشاشة وحده غير كافٍ؛ البيانات يجب ألا تصل إلى غير المخول أصلًا. invite تنشئ نسخة من Decisions، تفرغ adaptations، وتستبدل السبب الشخصي بـwhy التحريري العام. تعرض anchor_issue عامة بدل اسم الشخص وحساسيته، وترجع member_names فقط. تبقى الأسعار والتجارب والرتب والنقاط من النتيجة المشتركة؛ لا ندّعي إخفاء كل استنتاج ممكن عن المجموعة.

## middleware.py وملفات الويب

ASGI يستعمل scope لوصف الاتصال وreceive لاستلام الرسائل وsend للرد. ResponsePolicyMiddleware تمرر الاتصالات غير HTTP، وتلف send لإضافة nosniff وno-referrer وno-store لمسارات API والدعوة. ترفض Content-Length غير مقبول أو أكثر من 16384 بايت، وتعد البايتات أيضًا أثناء قراءة الجسم لأن الرأس قد يغيب. تعيد تسليم الجسم مرة واحدة إلى FastAPI بعد فحصه. هذه حماية حجم، وليست نظام rate limiting.

مسار `/api/{path:path}` غير المعروف يعيد 404 قبل mount ملفات الويب. لو كان dist موجودًا وقت تحميل التطبيق، `/join/{code}` يعيد index.html، وStaticFiles تقدم JavaScript والصور وغيرها. بعدها React تقرأ الرمز من URL وتطلب API. لهذا نبني web قبل تشغيل الخادم؛ إضافة dist بعد تشغيل عملية لم تره قد تحتاج إعادة تشغيلها.

تمرين: تتبعي لماذا لا يستطيع مفتاح العضو تغيير slots حتى لو عدل JavaScript محليًا وأظهر زر الإدارة.
