## البرنامج والملف والتشغيل

البرنامج تعليمات تنفذ بالترتيب، مع فروع وتكرار واستدعاء دوال. الملف يجمع تعليمات ذات علاقة. المجلد يجمع ملفات. كتابة ملف لا تشغله: Python يفسّر ملفات الخلفية، وMetro يحزم JavaScript للواجهة، وPostgreSQL تنفذ SQL، وXcode يبني الجزء الأصلي للآيفون.

Terminal مكان لإرسال أمر إلى نظام التشغيل. `cd` يغير مجلد العمل. `npm run api` يبحث عن اسم `api` داخل scripts في package.json ثم ينفذ نص الأمر. المكتبة كود نستدعيه؛ الإطار مثل React أو FastAPI يستدعي بعض كودنا وقت الحاجة.

| الامتداد | ما تقرئينه |
|---|---|
| .py | Python: الخادم والخوارزمية والاختبارات |
| .ts | TypeScript: JavaScript مع معلومات أنواع |
| .tsx | TypeScript يحتوي وصف واجهة JSX |
| .sql | إنشاء الجداول أو قراءة وتعديل البيانات |
| .json | صيغة بيانات، مفاتيح نصية وقيم، بلا تعليقات |

## القيم والمتغيرات

مثال تعليمي، ليس ملفًا جديدًا في التطبيق:

```python
budget = 100
name = "أمل"
vegetarian = True
cuisines = ["سعودي", "إيطالي"]
preferences = {"name": name, "budget": budget}
```

`=` يخزن مرجعًا لقيمة في اسم. العدد 100 من نوع int، الاسم str، وTrue من نوع bool. القائمة `[]` تجمع عناصر مرتبة؛ أول عنصر `cuisines[0]`. القاموس `{}` يربط مفتاحًا بقيمة، فنقرأ `preferences["budget"]`. لا تتطابق القائمة والقاموس حتى لو احتويا بيانات متشابهة.

```typescript
const budget: number = 100;
const name: string = "أمل";
const cuisines: string[] = ["سعودي", "إيطالي"];
const preferences = { name, budget };
```

`const` يمنع إعادة إسناد الاسم، لكنه لا يجعل محتوى الكائن غير قابل للتغيير. `: number` معلومة يفحصها TypeScript قبل التشغيل؛ ليست حماية لطلب يصل إلى الخادم. `{ name, budget }` اختصار `{ name: name, budget: budget }`. JavaScript تستخدم `true` و`false`، بينما Python تستخدم `True` و`False`.

## الشرط والدالة والحلقة

```python
def fits_budget(price: int, budget: int) -> bool:
    return price <= budget

for price in [45, 95, 180]:
    if fits_budget(price, 100):
        print(price)
```

`def` يعرّف دالة، والاسم بعدها هو طريقة استدعائها. price وbudget مدخلان. `-> bool` وصف للنتيجة، و`return` يعيدها إلى المستدعي. المسافة البادئة تحدد ما داخل الدالة وما داخل الشرط. الحلقة تزور الأعداد بالتتابع، وستطبع 45 ثم 95. `<=` مقارنة؛ `==` يسأل عن التساوي، و`=` ليس مقارنة.

في JavaScript: `const fitsBudget = (price: number, budget: number) => price <= budget;`. السهم يعرّف دالة، ولا يعني أن الخادم تلقى طلبًا. يجب أن يستدعيها كود آخر.

## الكائن والنموذج

`class Preferences(Model)` تعرّف شكل بيانات يرث سلوك Model. `Preferences(name="أمل")` يصنع كائنًا ويشغّل تحقق Pydantic. `self` هو الكائن الجاري العمل عليه. نماذج Pydantic هنا ليست جداول أو ORM؛ لن يحفظ استدعاؤها شيئًا في PostgreSQL دون SQL.

## الأخطاء والانتظار

`try` يحاول تنفيذ جزء قد يفشل، `except` في Python و`catch` في JavaScript يعالجان الفشل، و`finally` ينفذ التنظيف في الحالين. `raise` و`throw` يرفعان خطأ إلى المستدعي. لا تكتبي catch فارغًا إلا إن كان الخطأ عولج فعلًا في مكان واضح.

`async` تعرّف عملًا يمكن أن ينتظر، و`await` ينتظر نتيجته داخل ذلك العمل. `Promise` وعد بنتيجة مستقبلية، مثل رد HTTP. `Promise.all` ينتظر أعمالًا مستقلة بدأت معًا. `void load()` يعني أننا لا نستخدم الوعد هنا، وليس أن الفشل مستحيل؛ يجب أن تعالجه load.

`with connect() as db` يدخل موردًا له بداية ونهاية. `yield db` في context manager يسلم الاتصال إلى جسم with ثم يستأنف التنظيف عند الخروج. لا تخلطيه مع return الذي ينهي الدالة مباشرة.

## HTTP وJSON

العميل يرسل عنوانًا وطريقة ورؤوسًا، وقد يرسل body. الخادم يعيد status ورؤوسًا وbody. JSON نص متفق عليه لنقل الكائنات، و`JSON.stringify` يحول كائن JavaScript إلى نص، و`response.json()` يقرأ النص كقيمة.

```http
PUT /api/groups/GROUP_ID/settings
Authorization: Bearer OWNER_TOKEN
Content-Type: application/json

{"slots":1,"anchor_id":"fire","pocket_ids":[],"completed_ids":[]}
```

هذه أسماء توضيحية وليست بيانات وصول حقيقية. GET يقرأ، POST ينشئ هنا، PUT يستبدل الإعدادات أو التفضيلات، DELETE يحذف عضوًا. 200 نجاح، 201 إنشاء، 404 مورد غير متاح أو وصول غير صالح في هذا التطبيق، 409 تعارض سعة، 413 جسم كبير، 422 مدخلات غير مقبولة، 503 تعذر خدمة قاعدة البيانات. الرقم 0 في ApiError محلي من العميل؛ ليس رمز HTTP صادرًا من الخادم.

تمرين: اشرحي لماذا `{ "slots": "1" }` تختلف عن `{ "slots": 1 }`، ولماذا تغيير نص الزر إلى «محفوظ» لا يثبت وجود البيانات في DB.
