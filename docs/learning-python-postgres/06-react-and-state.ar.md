# 06 · الواجهة: البيانات التي تتغير تغيّر ما ترينه

[الفهرس](README.ar.md) · [التالي: الشاشات](07-screens.ar.md)

مكوّن React دالة تصف واجهة انطلاقًا من props وstate. props تأتي من الأب، مثل group. state قيمة يحتفظ بها React ويعيد الرسم عند تحديثها، مثل التبويب المختار. JSX مثل `<Button label="حفظ" />` وصف مكوّن، وليس نص HTML بالضرورة: React Native يحوله إلى عناصر المنصة.

## مثال حقيقي صغير

```tsx
const [draft, setDraft] = useState(slots);
useEffect(() => setDraft(slots), [slots]);
```

من MealControl: draft هو رقم السعة الجاري اختياره، وsetDraft طلب تحديثه. القيمة الأولى تأتي من slots. effect تزامنه عندما تصل slots جديدة من الخادم. تحريك slider يحدث draft فقط، ثم زر التأكيد يرسل onChange. لم نكتب إلى DB لمجرد أن الرقم الظاهر تغير.

`[slots]` قائمة اعتماد؛ effect تعاد إذا تغيرت القيمة. `[]` يعني عند تثبيت المكوّن مع تنظيف عند إزالته، وقد يعيد React في أدوات التطوير بعض التشغيل لاكتشاف مشاكل التنظيف. return داخل effect يعيد دالة تنظيف مؤقت أو listener. لا تستدعي hooks داخل if يختلف من رسم لآخر. [مبادئ React](https://react.dev/learn).

`useRef` يحتفظ بقيمة لا تعيد الرسم وحدها، مثل رقم إصدار طلب أو مرجع ScrollView. `useCallback` يحتفظ بهوية دالة إلى أن تتغير اعتمادياتها؛ لا يجعل ردها محفوظًا في DB ولا ينفذها من تلقاء نفسه.

## أول ملف: index.ts ثم App.tsx

registerRootComponent يسجل App كنقطة البداية. App يحمل أربعة أوزان خط. ينتظر حتى ينجح التحميل أو يظهر fontError ثم يكمل، كي لا يعلق التطبيق إلى الأبد على spinner بسبب الخط.

SafeAreaProvider يوفر حدود الشاشة الآمنة. View يملأ المساحة، WebDocument ينفذ تهيئة المتصفح فقط، وStatusBar يضبط لون عناصر شريط النظام. على الآيفون نرسم Organizer. على الويب نستخرج رمز `/join/...` بتعبير منتظم ونرسم InviteScreen. query `preview=organizer` أداة معاينة للمطور، وليست صلاحية إدارة؛ الخادم ما زال يحتاج مفتاح مجموعة.

## client.ts: مكان واحد لاتصال الشبكة

أنواع Preferences وGroup وغيرها مأخوذة من schema.d.ts المولدة. Session هنا `{groupId, token}` لحفظ وصول المنظم؛ ليست جلسة حساب في DB.

| المنصة | أين تتصل الـAPI؟ | من أين يأتي رابط الدعوة؟ |
|---|---|---|
| المتصفح | نفس origin؛ API_ORIGIN نص فارغ | window.location.origin |
| iOS Simulator | localhost:8000 على الماك | EXPO_PUBLIC_API_URL المدمجة في البناء |
| iPhone حقيقي | EXPO_PUBLIC_API_URL | نفس العنوان العام |

localhost على الآيفون الحقيقي هو الآيفون نفسه؛ لهذا لا نعتمد عليه للوصول للماك. لا تغيري منطق المحاكي لتجعلي اتصاله معتمدًا على عمر نفق Cloudflare.

`request<T>` دالة مشتركة: T نوع النتيجة المتوقع. تبدأ AbortController ومهلة 12 ثانية، وتربط إشارة إلغاء اختيارية. fetch ترسل الطريقة، Content-Type، وBearer عند وجود مفتاح، وجسم JSON عند وجود body. 5xx تحول إلى رسالة الخدمة العامة. في بقية الأخطاء تقرأ detail إن كانت نصًا. الفشل الشبكي أو الإلغاء يظهر رسالة الاتصال ورقم 0. finally يزيل المؤقت وlistener.

`as T` بعد response.json لا يفحص JSON وقت التشغيل؛ مصدر الثقة الأساسي عقد الخادم واستجاباته المفحوصة. record api مجرد أسماء قصيرة لكل endpoint. مثل `api.settings(s, body)` يختار URL وطريقة PUT ومفتاح session، ثم يسند العمل إلى request.

## storage.ts: ذاكرة الجهاز الصغيرة

get وset وremove تختار AsyncStorage في الويب وSecureStore في native. كلاهما يحمل نصوصًا، لذلك نحول Session إلى JSON ثم نعيد قراءتها. readSession تتعامل مع غياب النص وJSON فاسد، وتفحص أن groupId وtoken نصان قبل استعمالهما. لا تثبت تلك القراءة أن المفتاح صالح؛ api.group هو من يسأل الخادم.

بيانات المجموعة الدائمة في PostgreSQL، والمفتاح المحلي وسيلة للوصول إليها. storage ليست بديل قاعدة البيانات. إعادة تثبيت التطبيق أو تغيير المتصفح أو domain قد يغير إمكانية العثور على المفتاح؛ لا توجد هنا استعادة حساب.

## useOrganizer.ts: مدير بيانات المنظّم

يحتفظ session وgroup وloading وbusy وerror. loading للتحميل الأول، busy لحفظ تعديل. writing ref يمنع بدء كتابة ثانية أثناء كتابة جارية، وepoch رقم يتغير عند بدء تعديل.

restore تقرأ المفتاح المحلي ثم المجموعة. 404 تعني وصولًا غير متاح فتزيل المفتاح المحلي. خطأ الشبكة يعرض رسالة ويحتفظ بالمفتاح لإعادة المحاولة؛ إزالة المفتاح عند كل انقطاع كانت ستفقد الوصول بلا داعٍ.

effect الثانية تبدأ polling كل 6 ثوانٍ وتحديثًا عند عودة التطبيق للنشاط. تتجاوز الطلب إذا كانت كتابة جارية أو طلب آخر جارٍ أو التطبيق في الخلفية. alive يمنع ردًا متأخرًا من تعديل مكوّن أزيل. التنظيف يمسح interval وlistener.

مثال مشكلة يعالجها epoch: بدأ GET قديم، ثم حفظتِ slots=1 وانتهى PUT، ثم وصل GET بقيمة slots=9. لو قبلناه سنعرض الماضي. كل GET يحتفظ بقيمة epoch وقت بدئه؛ لا يقبل الرد إذا تغير الرقم أو writing=true. هذا منع لردود polling القديمة داخل العميل، وليس نظام دمج بين جهازين.

run يضبط busy وerror وينفذ عملية. عند فشلها يخزن الرسالة ثم يعيد رمي الخطأ حتى يستطيع النموذج عرضه. finally يعيد writing وbusy. create تحفظ المفتاح قبل تحديث state. settings وprofile وremove تستدعي endpoint الموافق وتضع GroupView الجديدة في state.

في الشاشات قد يظهر catch فارغ بعد run لأن error سبق حفظها وتعرضها الصفحة. هذا وصف للربط الحالي، وليس نصيحة لإخفاء كل الأخطاء. في تنفيذك ارجعي دائمًا إلى مكان عرض الخطأ قبل إسكات الوعد.

تمرين: حددي أي القيم تعيد الرسم: `setBusy(true)` أم `writing.current = true`؟ ولماذا نستعمل الاثنين؟
