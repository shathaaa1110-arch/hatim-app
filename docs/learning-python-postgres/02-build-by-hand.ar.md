# 02 · كيف تبنينه من الصفر بيدك؟

[الفهرس](README.ar.md) · [التالي: PostgreSQL](03-postgresql.ar.md)

الترتيب الآتي إعادة بناء تعليمية منطقية اعتمادًا على الكود الحالي؛ ليس ادعاء بأن كل سطر كتب تاريخيًا بهذا الترتيب. لا تبدئي بنسخ 600 سطر من Organizer. ابدئي بمسار صغير يعمل من الشاشة إلى قاعدة البيانات.

## 1. حوّلي الفكرة إلى قواعد مكتوبة

اكتبي: العضو له ميزانية وتفضيلات، المجموعة لها سعة وجبات وركيزة، والتجربة لها سعر ومطبخ وقيود معروفة. ارسمي ثلاث تجارب وثلاثة أشخاص على ورقة. حددي الفرق بين تفضيل يخفض النقاط وقيد يمنع الاختيار. اكتبي ماذا يحدث حين تصير السعة 1، وحين تتعارض الركيزة مع المجموعة.

معيار الانتهاء: تستطيعين تحديد النتيجة المتوقعة دون فتح محرر. ثم اكتبي قصص المستخدم وFigma والرسوم في مرحلة التصميم المدرسية. التطبيق المرجعي لا يغني عن ذلك.

## 2. تعلّمي اللغات في تمارين منفصلة

اكتبي برنامج Python يرشح قائمة حسب السعر، ثم يرتبها، ثم يشرح سبب الرفض. في JavaScript ابني كائنًا وقائمة ودالة filter. بعد ذلك تعلمي TypeScript والأنواع، ثم مكون React بزر يغير رقمًا. لا تربطي PostgreSQL قبل أن تفهمي تمرير قيمة إلى دالة وقراءة نتيجتها.

معيار الانتهاء: من دون الرجوع للحل، تضيفين شرطًا جديدًا وتكتبين مثالًا يثبت أثره.

## 3. جهزي مشروعك الخاص

أنشئي مجلدًا باسم مختلف، ومستودعًا لتاريخ عملك الفعلي. ابدئي بخادم Python صغير وبيئة افتراضية. المشروع الحالي يستعمل uv: `pyproject.toml` يعلن المكتبات و`uv.lock` يثبت الإصدارات. تعلمي أولًا تشغيل ملف Python، ثم مسار FastAPI واحد يرجع JSON.

للواجهة اختاري قالب TypeScript بسيطًا من create-expo-app، وافحصي package.json الناتج بدل افتراض أن latest يساوي نسخة المرجع. النسخة المشروحة Expo 57 مع React Native 0.86 وReact 19.2.3؛ راجعي [توثيق Expo 57](https://docs.expo.dev/versions/v57.0.0/) قبل تثبيت مكتباته. `npx expo install` يختار الحزم المتوافقة مع SDK المشروع. توليد هيكل بداية لا يغني عن كتابة التدفقات، وقرار السماح بالقالب الدراسي للمدرسة.

معيار الانتهاء: شاشة تعرض اسم التطبيق، ومسار صحة يرد، وكل عضو فريق يشغلهما عنده. لا تعتبري تشغيل المستودع المرجعي مساهمة في إعادة بنائك.

## 4. ارسمي DB ثم اكتبي schema بنفسك

افهمي جدولَي النسخة الحالية في الدرس 03، ثم حددي مخطط نسختك الدراسية بما يشمل الحسابات. اكتبي SQL في ملف migration. شغليه على DB تدريبية فارغة. أدخلي مجموعة وعضوين يدويًا واستعلمي عن أعضاء مجموعة واحدة باستخدام foreign key.

ابدئي بخادم PostgreSQL محلي في Docker أو خادمك المستضاف. احتفظي بكلمة المرور في env للخادم. لا تضعيها في تطبيق الآيفون أو EXPO_PUBLIC. لا تتدربي على قاعدة بياناتك الشخصية الموجودة هنا.

معيار الانتهاء: بيانات تبقى بعد إغلاق اتصالك، وصف عضو بمعرف مجموعة غير موجود يُرفض. اكتبي تجربة rollback تظهر أن نصف عملية إنشاء لا يبقى محفوظًا.

## 5. ابنِي أول رحلة كاملة

اجعلي زرًا يرسل نموذجًا بسيطًا إلى FastAPI، يتحقق الخادم منه، يحفظه في PostgreSQL، ويرجع id، ثم تعرضه الشاشة بعد إعادة القراءة. ابدئي بحقل الاسم؛ أضيفي الميزانية بعد نجاح الرحلة. تحققي من مدخل فارغ، ومن تعطل الخادم، ومن إعادة فتح التطبيق.

في النسخة المدرسية، خططي للمصادقة مبكرًا: إنشاء الحساب والدخول والخروج قبل الاعتماد على الوصول إلى مجموعات خاصة. لا تعيدي بناء النموذج بلا حسابات ثم تفترضي أنه يحقق مرحلة المصادقة.

معيار الانتهاء: يمكن تفسير كل انتقال «زر → fetch → route → validation → SQL → response → state».

## 6. اكتبي planner كدالة مستقلة

تأخذ catalog وmembers وsettings، وترجع plan. لا fetch ولا SQL داخلها. اكتبي فحص القيود أولًا، ثم النقاط، ثم ترتيبًا ثابتًا، ثم قص القائمة حسب الخانات. اختبري أن تقليص الوقت وحده لا يبدل ترتيب الناجين، وأن الركيزة الممنوعة لا تستبدل بصمت.

معيار الانتهاء: مثالان تحسبينهما على الورق يطابقان اختبارك. الأرقام 70% و30% قرار منتج في هذا النموذج؛ ليست معادلة علمية تثبت رضا كل الأشخاص.

## 7. أضيفي المجموعة والدعوة والجيب والإكمال

اكتبي كل رحلة وحدها. حفظ الجيب اليدوي يختلف عن التأجيل بسبب الوقت. الإكمال يستهلك خانة. تغيير ملف عضو يعيد حساب المجموعة. حد العضوية يفحص داخل معاملة تقفل المجموعة، وليس في JavaScript فقط.

معيار الانتهاء: متصفح عضو منفصل لا يستطيع استعمال مفتاحه لإدارة المجموعة. اجعلي الواجهة تعرض فقط نسخة البيانات المسموح له بها.

## 8. أضيفي التصميم بعد السلوك الأساسي

استخرجي T وButton وSheet وExperienceCard عند تكرار الحاجة. وحّدي الألوان والخطوط. أضيفي الصور ثم RTL ثم الحقول والأزرار القابلة للوصول. أضيفي Expo UI والزجاج مع بديل للمنصات الأخرى. اختبري الشاشات الصغيرة وحجم الخط وحالات الفراغ والفشل.

معيار الانتهاء: لو أزلنا الزجاج والصور يبقى التطبيق قادرًا على إنشاء خطة صحيحة. الزجاج يحسن الشكل، ولا يحسب أي قرار.

## 9. افصلي التجربة المؤقتة عن النشر

شغلي الاختبارات على قاعدة تدريبية، ثم صدّري واجهة الويب وشغلي FastAPI. Cloudflare يعطي عنوانًا لاختبار الأعضاء؛ لا ينقل PostgreSQL إلى السحابة. ابني Release في Xcode لتجربة الآيفون دون Metro. لخطة المدرسة اختاري نشرًا يستمر لدى الفريق وخطة إعادة تشغيل ونسخ احتياطي.

## جلسة عمل يومية مقترحة

20 دقيقة قراءة توثيق، 45 دقيقة تنفيذ صغير، 20 دقيقة اختبار، و10 دقائق كتابة ما تعلمتِه. عدّلي الوقت حسب خبرتك؛ ليست وعدًا بإنهاء مشروع كامل في أيام. لا تنتقلي للمرحلة التالية إذا كنتِ لا تستطيعين تفسير فشل بسيط في الحالية.

في Git احفظي إنجازًا صغيرًا واضحًا برسالة تصفه، مثل «أضفت تحقق الميزانية». لا تصنعي تاريخ commits وهميًا، ولا سجلات تعلم تصف عملًا لم تقومي به.
