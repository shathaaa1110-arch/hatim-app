# الملفات المولّدة والبيانات والأصول

[فهرس الكود](README.ar.md) · [درس الأدوات](../09-tooling.ar.md)

هذه الملفات جزء من فهم المستودع، لكنها تختلف عن دالة نكتبها لحساب الخطة. نوضح بنيتها وطريقة إنتاجها وقراءتها، ونربط الملف الكامل بدل نسخ آلاف سجلات الاعتماد المتكررة. جميع الأوصاف هنا تخص نسخة المصدر `59d45d3`.

## backend/openapi.json — عقد الشبكة

[افتحي الملف الكامل](../../../backend/openapi.json). تنتجه `app.openapi()` عبر [export_openapi.py](backend-hatim-export_openapi.py.ar.md). لا تشغّليه كبرنامج ولا تجعليه قاعدة البيانات.

تخيلي العقد كقائمة توضح: أي عنوان يُستدعى؟ بأي طريقة؟ ما البيانات المطلوبة؟ وما شكل الرد؟ هذا يتيح قراءة API دون فتح كل دالة Python.

| المفتاح | معناه في الملف |
|---|---|
| openapi | إصدار صيغة الوصف3.1.0، وليس إصدار Python |
| info.title / info.version | اسم API وإصدار التطبيق1.0.0 |
| paths | عشرة أنماط عناوين، بعضها له أكثر من طريقة؛ مجموع العمليات11 |
| get / post / put / delete | طريقة HTTP تحت العنوان |
| operationId | اسم مولد يميز العملية لتوليد الأدوات والأنواع |
| parameters | قيم المسار مثل group_id ورأس authorization؛ required يحدد الإلزام |
| requestBody | شكل JSON المرسلة وكون الجسم مطلوبًا |
| responses | حالات مثل200 و201 و422 ووصف أجسامها |
| content.application/json | نوع الجسم الذي يفهمه الطرفان |
| schema | وصف النوع؛ قد يكون كائنًا أو قائمة أو مرجعًا |
| $ref | رابط داخلي لتعريف بدل تكراره، مثل #/components/schemas/Preferences |
| components.schemas |13 نموذجًا تصف الطلبات والردود والتجارب والخطط |
| properties / required | حقول الكائن وما يجب إرساله منها |
| type / items / enum | النوع، ونوع عنصر القائمة، والقيم المحددة |
| default / minimum / maximum | القيمة الافتراضية وحدود العدد |
| minLength / maxLength / maxItems | حدود النص أو طول القائمة |
| anyOf مع null | أكثر من احتمال صالح مثل نص أو null |
| additionalProperties: false | لا حقول إضافية خارج التعريف |

مثلًا للوصول إلى طلب تعديل الإعدادات: ابدئي من `paths` ثم `/api/groups/{group_id}/settings` ثم `put` ثم `requestBody`. مرجع Settings يقود إلى القيود التي عرفناها في Pydantic. `422` يشير إلى ErrorResponse ذات `detail` نصية، مطابقًا لمعالج الخطأ الحالي. التحقق المركب مثل عدم وضع الركيزة في الجيب مكتوب في Python؛ ليس كل شرط عمل ظاهرًا تلقائيًا في JSON Schema.

رأس authorization موصوف كمعامل Header في هذه النسخة؛ لا يوجد إعداد OAuth2 أو securitySchemes مولّد لمجرد أن النص يبدأ بـBearer. التحقق من البصمة فعلي داخل دوال require في main.py.

## src/api/schema.d.ts — أنواع للواجهة

[افتحي الملف الكامل](https://github.com/shathaaa1110-arch/hatim-app/blob/59d45d33cbd6995a07a9b68236dd9de9aaf2b713/src/api/schema.d.ts). ملف `.d.ts` يصف أنواعًا ولا يشغّل شبكة. نولده من OpenAPI بواسطة [generate-types.mjs](scripts-generate-types.mjs.ar.md).

من المصدر نفسه:

```typescript
export type Preferences = components["schemas"]["Preferences"];
```

السطر أعلاه في client.ts: `components` واجهة مولدة، و`schemas` قسم النماذج، و`Preferences` النوع المطلوب. هذه طريقة الوصول إلى نوع داخل نوع، وليست قراءة استجابة JSON فعلية.

| القسم | كيف تقرئينه؟ |
|---|---|
| paths | يربط كل مسار بطرقه وoperations المناسبة |
| parameters | query وheader وpath وcookie؛ never يعني عدم وجود قيمة مقبولة في ذلك الموضع المولد |
| operations | تفاصيل requestBody وresponses لكل عملية |
| components.schemas | أنواع مثل Member وSettings وPlan |
| `?:` | الخاصية اختيارية في الوصف؛ ليست دائمًا غير موجودة في الرد الفعلي |
| `"مقيم" \| "زائر"` | اتحاد قيم نصية؛ يمنع كتابة قيمة ثالثة أثناء فحص TS |
| `string[]` | قائمة نصوص |
| `string \| null` | نص أو غياب صريح |
| `Record<string, never>` | لا مفاتيح ذات قيم مستخدمة في هذا القسم |

Pydantic تسمح بإغفال حقل له default في الطلب. لذلك قد ينتج النوع العام حقولًا اختيارية مثل cuisines رغم أن الرد المتسلسل يضم القيم الافتراضية. لهذا تستعمل الواجهة `?? []` و`?.` أحيانًا. الأنواع ليست تحققًا من JSON وقت التشغيل؛ `request<T>` يفترض العقد بعد قراءة الرد.

إذا غيرت حقلًا في Python: عدلي الاختبارات، ثم صدّري العقد وولدي الأنواع وافحصي TypeScript. لا تصلحي schema.d.ts يدويًا، فالتوليد سيستبدل التغيير.

## package-lock.json — شجرة حزم JavaScript

[افتحي الملف الكامل](../../../package-lock.json). `package.json` تقول ما يحتاجه مشروعك مباشرة؛ lock تحفظ الإصدارات الفعلية لكل الحزم التي تحتاجها تلك الحزم أيضًا.

- `lockfileVersion` إصدار صيغة npm.
- `packages[""]` معلومات حزمة المشروع نفسها.
- `packages["node_modules/..."]` سجل حزمة داخل الشجرة، وليس دليلًا أنك كتبت مصدرها.
- `version` الإصدار المحلول، و`resolved` مصدر التنزيل، و`integrity` بصمة محتوى للتحقق منه.
- `dependencies` احتياجات الحزمة، و`peerDependencies` متطلبات توافق مع الحزمة المستضيفة.
- `engines` شروط مثل نسخة Node، و`optional` أو `dev` تصنيف دور الاعتماد.
- `bin` أو `hasInstallScript` توضح وجود أداة تشغيل أو خطوة تثبيت إن وردت.

لا تحفظ هذه السجلات مجموعات حاتم ولا أسرار المستخدم. اكتبي الاعتمادات المقصودة بأوامر npm المناسبة، ودعي npm تحدث القفل. `npm ci` يستعمله لإعادة تثبيت الشجرة. لا تحذفي القفل لتجاهل تعارض دون فهمه.

## backend/uv.lock — شجرة حزم Python

[افتحي الملف الكامل](../../../backend/uv.lock). `version` و`revision` هنا لصيغة القفل، و`requires-python` يحدد بيئة الحل.

`[[package]]` في TOML تعني إضافة عنصر إلى قائمة packages. كل عنصر له name وversion وsource وdependencies. `sdist` أرشيف المصدر، و`wheels` حزم مبنية مسبقًا لمنصات مختلفة؛ hash وsize للتحقق. `marker` شرط بيئة، مثل نسخة Python، لا شرط منطق المجموعة. الحزمة المحلية تعلن اعتمادها أيضًا.

`uv sync --locked` تعيد البيئة وفق هذا القفل أو ترفض عدم اتساقه مع تعريف المشروع. إضافة مكتبة مقصودة تغير pyproject وlock معًا. لا تكتبي بصمات wheels أو عناوين تنزيلها يدويًا.

## planner-parity.json —180 حالة مرجعية

[افتحي بيانات الاختبار كاملة](../../../backend/tests/fixtures/planner-parity.json). هي قائمة حالات اصطناعية، لا بيانات DB للمستخدمة. كل حالة تحتوي ثلاثة مفاتيح:

```text
members  → مدخلات الأشخاص
settings → مدخلات الخانات والركيزة والجيب والمكتمل
plan     → النتيجة المرجعية المتوقعة
```

الحالة الأولى فيها `members=[]` و`slots=1` و`anchor_id="fire"`. النتيجة تختار fire بنقاط96، وتؤجل التجارب الثماني الأخرى، وتعيد consumed=0 وavailable=1 وunfilled=0. عدم وجود أعضاء هنا حد تختبره الدالة النقية؛ تدفق API لإنشاء مجموعة يضيف المنظم بالفعل.

بقية الحالات تغير المدخلات وتحفظ النتيجة بنفس النماذج التي شرحناها. [test_planner.py](backend-tests-test_planner.py.ar.md) يتحقق من كل حالة بواسطة parametrize. الحفاظ على نتيجة قديمة لا يثبت أنها صحيحة في كل موقف؛ اختبارات الخصائص المستقلة تتحقق أيضًا من القواعد. لا تعيدي توليد النتائج لمجرد جعل اختبار أحمر أخضر دون تفسير تغير السلوك.

أما [legacy.sql](backend-tests-fixtures-legacy.sql.ar.md) فهي بيانات SQLite اصطناعية لاختبار النقل إلى PostgreSQL، وقد شُرحت كاملًا. وجودها لا يعني تشغيل SQLite في الباك إند الحالي.

## ملفات أدوات المساعدة

[AGENTS.md](../../../AGENTS.md) تعليمات لأداة برمجة بمراجعة توثيق Expo57. [CLAUDE.md](../../../CLAUDE.md) يحيل إلى الملف الأول. [.claude/settings.json](../../../.claude/settings.json) تضبط `enabledPlugins` لإضافة Expo في أداة مساعدة.

## ما هو خارج كود المشروع المشروح؟

`node_modules` وبيئة Python الافتراضية مصدر مكتبات خارجية. `ios/` و`android/` هنا مشاريع أصلية مولدة من إعداد Expo. `dist/` حزمة الويب المجمعة. `.run/` وtest-results نواتج عمل مؤقتة. بيانات DB وملفات env الخاصة ونسخ SQLite القديمة ليست مادة ننسخها إلى كتاب عام.

فهرس الكود يغطي جميع ملفات التطبيق والخادم والاختبارات والسكربتات والإعدادات النصية المتتبعة في النسخة المرجعية، وتغطي هذه الصفحة الملفات المولدة وبقية الأصول. الأدلة التعليمية نفسها شرح وليست جزءًا من تنفيذ المنتج. لا حاجة لقراءة ملايين أسطر المكتبات كي تفهمي القرار الذي كتبتِه، لكن يجب أن تفهمي وظائفها وحدود العقد الذي تستخدمينه منها.
