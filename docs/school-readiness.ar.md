# متطلبات المدرسة — الحالة الحالية

مراجعة 15 سبتمبر 2026 لنسخة Python + PostgreSQL على `codex/persistent-groups`. هذا سجل لما ينفذه المستودع وما بقي للتسليم؛ ليس شهادة قبول من المدرسة.

قُرئت [المتطلبات التقنية](https://hoblertonschool.notion.site/Portfolio-Project-Technical-Requirements-311204290bfc8076ac82d9867899af46) و[خطة المراحل](https://hoblertonschool.notion.site/Portfolio-Project-Meetings-Plan-397204290bfc8077b41fe6333d5b9f16) من المتصفح. تشترطان قاعدة بيانات وAPI وواجهة ينفذها الطالب، مصادقة خاصة بالمشروع، CRUD كاملًا، تحققًا من المدخلات والأخطاء، وتوثيقًا واختبارات ونشرًا. تصميم Figma وتسليمات الفريق والعرض جزء من المراحل أيضًا. نموذج Tally المرتبط سابقًا مغلق عند هذه المراجعة؛ لم يُعامل كمصدر متاح حديثًا.

## المقارنة مع الكود

| المطلوب | الحالة والدليل |
|---|---|
| تسجيل/دخول/خروج عبر الواجهة والخادم وDB | منفذ. زر «حسابي» في الرئيسية، وAuthScreen وAccountProvider، ومسارات auth وجدولا accounts/account_sessions. كان المدخل محصورًا داخل القروبات، وأصبح مستقلًا. |
| تخزين آمن لكلمات المرور وجلسات | Argon2، جلسات عشوائية مخزنة كبصمات لمدة30 يومًا، وإلغاء الجلسة الحالية عند الخروج. لا خدمة Auth جاهزة. |
| صلاحيات الخادم | الخطة للحساب المالك أو مفتاح الضيف غير المرتبط فقط. القروبات تحافظ على المالك والقائد والعضو، واختبارات تمنع الوصول بين حسابين. |
| CRUD أساسي من الشاشة إلى DB | إنشاء خطة، قائمة الخطط وفتحها، تغيير الاسم والإعدادات والذوق، حذف الخطة بتأكيد. حذفها يوقف الدعوة ويحذف بيانات رفقتها دون المساس بحسابها أو بقية الخطط. |
| بيانات المشروع في DB وتصميم وترحيلات | PostgreSQL؛ 15 جدولًا. ترحيل003 يضيف ملكية الحساب إلى الخطة، والترحيل002 يبذر كتالوج التجارب. الاكتشاف والمحركان يقرؤون الكتالوج من DB. |
| تحقق وتحميل وأخطاء | Pydantic ورسائل عربية، حالات تحميل وإعادة المحاولة، وحفظ التغيير لا ينجح شكليًا عند503. expected يمنع مسح إعدادات جهاز آخر. |
| API موثق | OpenAPI وSwagger على /api/docs؛ أنواع TypeScript مولدة، و[عقد التخطيط](api-planning.ar.md) و[عقد القروبات](api-social.ar.md). |
| المعمارية وERD وتسلسل الطلبات | [المعمارية الحالية](architecture-python-postgres.ar.md) و[شرح الحساب والخطة](learning-python-postgres/16-accounts-and-school.ar.md). |
| قصص المستخدم وأولوية العمل وSCM/QA | [خطة العمل والتحقق](school-delivery-plan.ar.md). توضح المنفذ ومعايير القبول دون اختلاق مهام أو مساهمات لأفراد. |
| نشر النظام | Dockerfile وCompose جاهزان لاختيار الاستضافة. Cloudflare للتجربة المؤقتة. النشر الدائم مؤجل باختيار صاحبة المشروع، وليس منجزًا. [دليل النشر](deployment.ar.md). |

## ما بقي خارج هذه الإضافة

- Figma: يلزم ملف تصميم قابل للتحرير وتسليمه فعليًا؛ شاشات التطبيق ولقطات الاختبار لا تعني وجود ملف Figma.
- النشر: اختيار استضافة وخادم PostgreSQL وعنوان HTTPS، إعداد الأسرار والنسخ الاحتياطي، ثم اختبار الاتصال من أجهزة الفريق. لم تُنشأ خدمة مدفوعة أو حساب استضافة.
- العمل الجماعي: اعتماد الميثاق وتقسيم الأدوار وخطة الأسابيع ولوحة إدارة المشروع، وتجربة تشغيل مستقلة لكل عضو.
- العرض والملصق وصفحة التعريف النهائية: تحتاج محتوى الفريق واعتماده. جذر الويب الحالي مدخل الدعوات، وليس صفحة تسويق نهائية ادّعينا تسليمها.
- سجل التعلّم والمساهمات: يكتبه كل شخص من عمله الحقيقي. الكود المرجعي هنا بُني بمساعدة AI؛ لا يوصف بأنه تنفيذ الطالب المستقل. مرجع قبول استخدامه هو المدرسة.

## ما لم أضفه باعتباره شرطًا

لم تظهر في الصفحتين المقروءتين ضرورة JWT تحديدًا، أو تسجيل اجتماعي، أو استعادة كلمة المرور، أو لوحة تحرير للتجارب، أو دفع أو SMS أو Temporal. الجلسات الحالية تلبي أسلوب المصادقة، وCRUD الخطط يبرهن المسار الكامل. الكتالوج ما زال تحريريًا ببيانات توضيحية؛ لا يستطيع المستخدم العادي تغيير توصيات جميع الناس.

الاختبارات الجديدة تغطي استعادة الخطط على متصفح آخر، الفصل بين الحسابات، إلغاء الجلسات، نقل خطة الضيف دون تغيير قيودها، الحذف، فشل الخدمة، ومصدر الكتالوج الحقيقي. نتائج التشغيل وحدودها مثبتة في الفصل16؛ لا تُنسب إلى عمل طالب مستقل.
